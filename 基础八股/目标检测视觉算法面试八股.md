# 目标检测视觉算法面试八股

> 面向视觉算法岗位技术面试。回答具体问题时应注明模型版本；YOLO 各代的检测头、分数与后处理并不完全相同。

完整流程版（包含数据、预处理、训练、推理与评估指标）：[目标检测全流程面试八股](目标检测全流程面试八股.md)。本篇保留为精简速记版。

## 一、先讲清任务与完整流程

**Q1：目标检测的输入输出是什么？**

输入通常是预处理后的图像张量 `[B,3,H,W]`。网络输出密集候选预测；解码和筛选后，每个检测结果通常表示为 `[x1,y1,x2,y2,score,class_id]`，坐标映射回原图。画框和类别文字属于可视化，不是模型输出所必需的步骤。

**Q2：从原图到结果经历什么？**

原图 → 缩放/letterbox/归一化 → Backbone 提取特征 → Neck 融合多尺度特征 → Head 预测框和类别 → 解码 → 置信度筛选 → 去重（常规 NMS，具体依模型）→ 坐标还原 → 可选可视化。预处理时必须保存缩放比例和补边量；否则还原的框会偏移。

**Q3：目标检测与图像分类、语义分割、实例分割有何区别？**

分类回答整张图属于什么类别；目标检测给每个实例的类别与边界框；语义分割给每个像素的类别但通常不区分同类实例；实例分割给每个实例的像素掩码。检测框是粗定位，掩码是像素级轮廓。

## 二、架构与检测头

**Q4：Backbone、Neck、Head 分别做什么？**

Backbone 提取层级特征；Neck 进行跨尺度融合；Head 把各尺度特征转换为边框与类别预测。以 640×640 输入为例，步长 8、16、32 对应的特征图常是 80×80、40×40、20×20。高分辨率层通常有利于小目标，但实际效果也受语义表达、训练与输入分辨率影响。

**Q5：为什么需要多尺度特征融合？FPN 与 PAN 如何理解？**

浅层保留更多空间细节，深层具有更强语义。FPN 的典型自顶向下路径把高层语义传给高分辨率特征；PAN 的典型自底向上路径加强定位信息的传递。面试中先讲信息流与目的，再说明具体 YOLO 版本的 Neck 结构。

**Q6：耦合头与解耦头有何区别？**

耦合头共享较多预测层，同时输出框、目标置信度和类别；解耦头把回归与分类分支分开，便于分别优化。YOLOv5 常见实现使用耦合检测头；YOLOv8 常见实现使用解耦头。不要把“解耦”理解为完全不共享前面特征。

**Q7：Anchor-based 与 anchor-free 有何区别？**

Anchor-based 在特征图位置放置预设尺寸/长宽比的框，预测相对偏移；anchor-free 不依赖这种预设宽高的 anchor，常基于特征点预测边界框。两者都需要确定预测位置和正样本分配规则。“Anchor-free”不等于没有网格点或参考点。

**Q8：以 YOLOv5 和 YOLOv8 为例，检测头输出如何不同？**

YOLOv5 的典型检测头在每个尺度的每个位置、每个 anchor 上预测 `4+C+1` 个值：4 个框参数、C 个类别值、1 个 objectness。若每处有 A 个 anchor，输出通道为 `A×(5+C)`。常规类别得分由 objectness 与对应类别概率相乘。

YOLOv8 的常规检测头为 anchor-free、分类与回归解耦；回归分支常输出四个方向的离散分布，并用 DFL 得到距离，分类分支输出 C 个类别分数，没有单独的 objectness 通道。640×640 输入、步长 8/16/32 时，候选位置数为 `80²+40²+20²=8400`。这里的 8400 是特征位置数，不是最后检测到的目标数。

**Q9：DFL 是什么？**

Distribution Focal Loss 把边框四边距离表示为离散分布而非直接回归单个数，再对分布求期望得到连续距离。这样可提供更细的定位监督。需区分训练时的 DFL 损失和推理时把分布转换为距离的操作。

**Q10：YOLO 与 DETR 的主要区别？**

常规 YOLO 检测器在多尺度特征上密集预测，通常需要 NMS 去重。原始 DETR 使用 object queries、Transformer 编解码结构与匈牙利匹配，按集合预测目标，通常不依赖传统 NMS；其早期版本收敛较慢，后续改进很多。不要把所有 YOLO 都说成必须 NMS：部分较新端到端变体支持无 NMS 推理。

**Q10a：一阶段与两阶段检测器如何区分？**

两阶段检测器先产生候选区域，再对候选区域分类并精修边框，Faster R-CNN 是代表。一阶段检测器直接在特征图上预测类别与框，YOLO、SSD、RetinaNet、FCOS 是常见代表。通常一阶段方案便于追求速度，但精度和时延都取决于具体模型、输入尺寸与部署环境，不能只凭阶段数判断。

**Q10b：Faster R-CNN 的流程和关键模块是什么？**

图像经 Backbone/FPN 得到特征；RPN 产生候选框；RoI Align 从特征图提取每个候选区域的固定尺寸特征；第二阶段分类并回归边框；推理时筛选与去重。RPN 回答“哪里可能有目标”，第二阶段回答“是什么、框要如何修正”。RoI Align 通过插值避免 RoI Pooling 的粗量化对齐误差。

**Q10c：RetinaNet 和 FCOS 常被问什么？**

RetinaNet 是使用 anchor 的一阶段检测器，Focal Loss 缓解前景/背景与难易样本不平衡；FCOS 是 anchor-free 一阶段检测器，从特征位置预测到框四边的距离，并使用中心度等机制降低低质量预测。Focal Loss 的核心是降低易分类样本对损失的主导，而不是简单增加正样本数量。

**Q11：YOLO 与 SAM 的区别？**

YOLO 检测模型通常自动输出训练类别的框与分数；原版 SAM 结合图像编码、提示编码和掩码解码，按点/框等提示输出类别无关的掩码，通常不直接给类别名。二者区别涉及任务、输入、结构和输出，不仅是解码器。可用 YOLO 框作为 SAM 提示获得更细的轮廓。若比较 YOLO-seg，应说明它也输出实例掩码。

## 三、训练与损失

**Q12：目标检测为什么需要正负样本分配？**

密集预测会产生大量候选位置。训练时必须确定哪些位置/候选负责哪一个真实框，其余作为背景或忽略样本。分配策略影响收敛、召回和小目标表现。常见依据包括位置、IoU、分类分数或二者组合；具体规则因版本而异。

**Q13：检测损失一般由哪些部分组成？**

通常包括边框定位损失和分类损失；有独立 objectness 分支的版本还包括目标置信度损失；采用分布式框回归的版本可能包含 DFL。框损失常见 IoU/GIoU/DIoU/CIoU 系列。损失项名称与权重应以具体实现为准。

**Q14：IoU、GIoU、DIoU、CIoU 的思路？**

IoU 为交集面积与并集面积之比；无交集时 IoU 为 0，难以表达框间距离。GIoU 结合最小外接框惩罚，DIoU 加入中心点距离，CIoU 进一步考虑长宽比。面试重点是说清每个改进试图解决的定位问题，而非只背公式。

**Q15：为什么使用数据增强？常见风险是什么？**

随机缩放、裁剪、翻转、颜色变化、Mosaic、MixUp 等可增加样本多样性。但过强增强可能制造不真实样本，裁掉小目标或破坏标注；训练末期有些实现会关闭强增强。针对具体任务应检查增强后的图和标签。

**Q16：类别不平衡与难例如何处理？**

先分析类别样本量、场景分布和标注质量；可采用重采样、类别权重、Focal Loss、难例挖掘、补采目标场景数据等。仅调 loss 权重未必解决长尾问题，评估时要看各类别 AP、误检和漏检案例。

## 四、推理后处理

**Q17：置信度筛选和 NMS 分别做什么？**

置信度阈值先移除低分候选；NMS 按得分排序，保留高分框并抑制与它重叠过高的候选，减少同一目标的重复框。阈值提高通常降低误检但可能增加漏检；需结合业务目标调参。

**Q18：NMS 的 IoU 阈值如何影响结果？**

阈值较低时抑制更激进，密集相邻目标可能被误删；阈值较高时保留更多重叠框，重复检测可能增多。还要注意是按类 NMS 还是跨类 NMS；多标签场景不能机械地全局去重。

**Q19：Soft-NMS 和传统 NMS 区别？**

传统 NMS 将重叠过高的候选直接删除；Soft-NMS 根据重叠程度降低其分数，密集目标场景可能减少误删，但会增加一定后处理开销，收益须以数据验证。

**Q20：letterbox 后如何还原坐标？**

若原图按比例 `r` 缩放并左右/上下分别补边 `pad_x`、`pad_y`，则输入图坐标还原为 `x_original=(x_input-pad_x)/r`、`y_original=(y_input-pad_y)/r`，再裁剪到原图宽高范围。应确认预处理和推理后处理所用的补边约定一致。

**Q21：模型输出后把框、类别名叠加到原图，算后处理吗？**

广义上可称为推理后的处理，但工程上最好区分：检测后处理负责解码、筛选、去重、坐标还原；可视化负责画框、类别名和分数。业务系统可直接消费结构化检测结果，不必生成标注图。

## 五、评价指标与误差分析

**Q22：Precision、Recall、AP、mAP 分别是什么？**

`Precision=TP/(TP+FP)`，关注预测为目标的结果有多少正确；`Recall=TP/(TP+FN)`，关注真实目标有多少被找出。不同置信度阈值形成 P-R 曲线，AP 概括单类别曲线表现；mAP 为类别 AP 的平均。TP 判定依赖类别与 IoU 阈值。

**Q23：mAP@0.5 与 mAP@0.5:0.95 有何区别？**

前者在 IoU=0.5 下计算；后者通常在 0.50、0.55、…、0.95 共十个阈值上平均，更严格地衡量框定位质量。报告指标时要注明数据集、类别、输入尺寸与评测实现。

**Q24：模型 mAP 高，线上效果却差，怎么排查？**

先核对线上与验证集的图像分布、预处理、类别映射、阈值和坐标还原；再按类别、目标尺寸、遮挡、光照、相机、场景切片统计误检漏检；最后检查标注一致性、时延限制和 NMS 设置。mAP 是数据集平均指标，不能替代业务场景下的精度、召回和时延目标。

**Q25：小目标检测困难在哪？如何改进？**

目标在下采样后占据像素少，纹理信息丢失，且容易受模糊、遮挡和标注误差影响。可尝试提高有效输入分辨率、增加高分辨率预测层、切图/滑窗、针对小目标采样及增强、优化标注与尺度分配。切图会引入边界重复和额外计算，需要合并结果。

## 六、部署与场景追问

**Q26：如何比较两个检测模型的速度？**

在同一硬件、推理框架、精度类型、输入尺寸、batch size、预热与同步方式下分别测模型前向耗时和端到端耗时。端到端耗时应包括解码、预处理、后处理及必要的数据传输。参数量和 FLOPs 不能直接代表真实时延。

**Q27：量化与剪枝会带来什么权衡？**

量化可减少存储和计算成本，但可能影响精度，尤其是小目标和边框定位；剪枝减少冗余参数/通道，但速度收益取决于硬件和算子支持。应比较同一评测集上的分场景 AP、端到端时延与资源占用，并检查部署端输出一致性。

**Q28：检测框抖动或视频中重复漏检怎么办？**

先排查光照、运动模糊、阈值、输入尺寸和 NMS；视频场景可以加入目标跟踪、时序平滑或轨迹级规则，但要注意延迟和错误累积。目标检测逐帧输出，稳定 ID 通常属于多目标跟踪任务。

## 七、面试时的一分钟回答模板

“目标检测模型输入是经过缩放、补边和归一化的图像张量。以常规 YOLO 为例，Backbone 提取多层特征，Neck 融合不同尺度，Head 在各尺度预测候选框和类别。推理时要解码预测、按分数过滤、根据具体模型做 NMS 或端到端去重，再把坐标映射回原图，得到框、类别和分数。画框写字只是结果可视化。训练时关键是正负样本分配、分类与定位损失；评价时看 mAP、各类 AP、误检漏检和端到端时延。具体谈检测头时需指明版本，例如 YOLOv5 有 anchor 和 objectness，YOLOv8 常规检测头为 anchor-free、解耦结构且没有独立 objectness。”

## 八、容易说错的点

- 不要把“模型直接输出”与“最终结构化结果”混为一谈。
- 不要说所有 YOLO 都有 anchor、objectness 或都必须做 NMS。
- 不要把 SAM 说成直接输出训练类别名称的常规目标检测器。
- 不要只报 mAP；面试项目题还要交代数据、指标口径、速度和失败案例。
- 不要忽略 letterbox 坐标还原与类别索引映射，它们是部署常见错误来源。
