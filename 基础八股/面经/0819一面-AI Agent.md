## agent面经
1. 自我介绍
> （略）30 秒：学校/专业 + 最相关的智能体项目（你负责哪块、量化结果）+ 技术栈关键词 + 投递理由。

2. 项目经历

第一段

1) workflow技术实现是怎么做的？
> 答：用 DAG 描述流程，节点分五类——LLM 节点、工具/HTTP 节点、条件分支节点、人工确认节点、结束节点；引擎按拓扑序调度，无依赖的节点并行、有依赖的等汇合。节点间用统一的 state（带 schema）传参，每步执行结果落库，所以支持重试、断点续跑和回放。分支条件可以是规则表达式，也可以是 LLM 判定（这时给结构化输出约束）。补一句"为什么不用纯 ReAct"：固定链路固化下来能省 token 且可控。

2) 你在项目中遇到有哪些问题，是怎么解决的？
> 答：STAR-L 结构，讲 2 个就够。示范一：工具调用参数经常缺字段或类型错 → 在工具层加 JSON Schema 校验 + 默认值填充 + 参数纠正重试，失败率从 12% 降到 1% 以内。示范二：长链路里某一节点超时拖垮整条流程 → 给每个节点独立超时 + 指数退避重试 + 熔断降级到备用实现，并保证写操作幂等，避免重试导致重复建单。

3) 你觉得你参与的部分有哪些难点
> 答：选"有技术取舍"的说。比如状态一致性：Workflow 有并行分支时，多个分支同时写 state 会互相覆盖，最后用"每个分支独立命名空间 + 汇合时合并"解决；再比如上下文裁剪点放在哪，裁早了丢信息、裁晚了超窗口，最后按"节点边界"裁而不是按轮次裁。

4) 你后续有考虑怎么优化这个项目吗？比如说自动化驱动运行检测
> 答：往"自动化 + 可观测 + 评测"三个方向讲：①自动化回归——把线上 badcase 沉淀成评测集，每次改 prompt/模型/工具都跑全量回归；②运行监测——全链路 trace + 成功率/时延/步数看板 + 异常自动告警，异常样本自动归集；③评测自动化——用 LLM-as-Judge 替代大部分人工抽检，人工只复核对齐；④灰度——新版本按流量比例放量，指标不达标自动回滚。

第二段

1) MCP和Skill的区别
> 答：MCP 是"工具怎么接"的标准协议：统一描述工具、参数和通信方式，让任意工具能被任意 Agent 复用，解决生态碎片化。Skill 是"一类任务怎么做"的能力包：把多个工具 + prompt 指引 + 操作流程 + 参考资源封在一起，按需渐进加载。一句话：MCP 是连接层（插头标准），Skill 是能力层（说明书 + 工具套装），Tool 是单个原子函数。

2) 简述下你理解的智能体构成
> 答：模型（决策大脑）+ 规划（任务拆解与调度）+ 工具（执行手脚）+ 记忆（短期上下文与长期偏好知识）+ 编排运行时（状态机、循环控制、超时重试）+ 安全与可观测（权限、审计、日志评测）。前四个决定"能不能干成"，后两个决定"敢不敢上生产"。

3) 说下你项目中使用到的redis的作用
> 答：四类用途——①缓存：会话上下文、用户偏好、工具/模型元数据、检索结果；②分布式锁：定时任务防重、库存预扣、缓存重建防击穿；③限流计数：滑动窗口 zset / 令牌桶；④短期记忆与状态：多轮会话的中间状态、任务进度。

4) 你项目中redis缓存的热点数据有哪些
> 答：按 QPS 排序取 Top：租户配置与配额、模型/工具注册表、词典与 prompt 模板、用户权限、会话上下文、高频检索结果。设计上说一句"热点 key 打散（加随机后缀）+ 本地二级缓存 + 逻辑过期防击穿"，面试官一般会顺着追问。

5) redis的分布式锁有用到哪些场景
> 答：跨实例需要互斥的短临界区：定时任务防重复执行、库存预扣/优惠券领取、消息幂等去重、缓存重建。实现用 SET key val NX PX，value 存唯一标识（如 UUID+线程号），释放时用 Lua 先比对再删，防止误删别人的锁；需要长任务就用 Redisson 看门狗续期。强一致场景要补一句"Redis 锁在极端主从切换下可能丢锁，会加 DB 唯一索引兜底"。

6) 你部署过哪些模型
> 答：文本类 Qwen2.5-7B/14B、Llama3-8B，多模态 Qwen-VL 系列，Embedding 用 bge-m3，rerank 用 bge-reranker。规模以 7B～32B 为主，量化用 AWQ 4bit。

7) 使用vLLM部署大模型有遇到哪些问题
> 爆显存、架包版本不匹配、延迟和吞吐跷跷板问题（减少批处理参数换更低延迟）、KV缓存爆满导致上下文限制8k左右、推理模式与解析器配置坑（关不掉思考模式）

第三段

1) 平时使用AI的场景有哪些，用哪些AI Coding工具
> 答：工具：Cursor / Claude Code / Copilot。场景：写样板代码和单测、读陌生代码库（先让它画调用链）、排查报错日志、写 SQL 和一次性脚本、生成文档与接口说明、梳理八股。挑一个讲效率提升的具体例子。

2) 你认为在工作中，AI充当了什么角色
> 答：定位是"高效但需要复核的初级执行者"——能把从想法到初稿的时间压缩很多，但判断、取舍和最终责任在人。所以我用它做执行和扩写，自己做定义问题与验收。

3) 你在实际开发过程中如何保证代码的准确性
> 答：五个动作——①给上下文（相关文件、接口定义、团队规范）；②给验收标准（先写测试，或写完必须跑通编译和单测）；③小步提交，一次只改一个关注点，方便 review；④自己必读 diff，重点看边界条件、异常分支、并发、资源释放、SQL 注入；⑤lint + 类型检查 + CI 做最后一道闸。

4) 分享下你和AI交互的一些经验
> 答：①先对齐方案再写代码，别一句话丢需求；②给约束比给形容词有用（"用 xx 库、不要新增依赖、保持函数签名不变"）；③给示例代码比描述风格有效；④一次一个关注点，别在一个 prompt 里塞五个任务；⑤让它自证——要求写测试并跑通，比让它"检查一下"可靠；⑥上下文脏了就重开对话，别在错误上加补丁。

5) 你觉得你投递这个岗位的优势是什么
> 答：三点式——技术栈匹配（会什么对应 JD 哪一条）+ 有落地经验（什么量级、多少 QPS/用户、拿到什么结果）+ 学习与协作（能快速上手陌生领域、能推动跨团队落地）。

### 手撕
长度最小的子数组（滑动窗口）
> 答：数组元素全为正，右指针扩张累加，当 sum >= target 时不断收缩左指针并更新最小长度，整体 O(n)。若含负数则滑窗失效，要改成前缀和 + 单调队列。
>
> ```python
> def minSubArrayLen(target: int, nums) -> int:
>     left = total = 0
>     ans = float('inf')
>     for right, x in enumerate(nums):
>         total += x
>         while total >= target:
>             ans = min(ans, right - left + 1)
>             total -= nums[left]
>             left += 1
>     return 0 if ans == float('inf') else ans
> ```
