2. 项目/实习经历
1) 实习经历/项目经历的收获
> 答：收口到三点——①工程认知从"能跑"变成"可控、可测、可运维"；②学会用指标说话（badcase 回流、改前改后对比）；③推动跨团队落地时的沟通方式。挑一点配一个具体例子，别泛泛而谈。

2) 手画你搭建的智能体框架
> 答：按五层画：接入层（API/会话/鉴权）→ 编排层（Router 选 ReAct / Plan / Workflow，状态机驱动、可中断可恢复）→ 能力层（工具注册中心、Skill 渐进加载、RAG 检索）→ 模型层（LLM 网关、多模型路由、限流计费）→ 支撑层（记忆存储、上下文压缩、日志埋点、评测）。画完必须顺着讲一次请求怎么流过去，否则图是死的。

3) 你认为智能体具备有哪些能力
> 答：六项——感知理解（解析意图、读工具返回）、规划（任务拆解与动态调整）、工具调用、记忆（短期上下文 + 长期偏好知识）、反思纠错（结果校验、重试、换策略）、安全可控（权限边界、高危动作人工确认）。

4) 企业级RAG出现检索不准确你怎么解决
> 答：分四层查。数据层：清洗、按结构/语义分块、带标题与元数据、表格单独处理；检索层：BM25 + 向量混合召回、query 改写、加 rerank 精排、元数据过滤；生成层：强制基于引用回答、无命中就说不知道；闭环层：建评测集看 Recall@K 与命中率，badcase 回流反推分块和召回策略。

5) AI Coding交互中如何保证最后代码交互质量高
> 答：给足上下文（相关文件、接口定义、团队规范、示例）+ 给验收标准（先写测试再写实现，或写完必须跑通编译与单测）+ 小步提交一次只改一个关注点 + 自己必读 diff 重点看边界/异常/并发/资源释放/SQL 注入 + 最后靠 lint、类型检查和 CI 兜底。

6) 你项目使用的智能体框架和dify这些有些有什么区别
> 答：Dify 是低代码可视化平台，上手快、适合业务同学快速搭标准应用，但深度定制受限；自研框架面向深度定制——自定义编排调度与状态机、自己的上下文压缩策略、私有协议工具接入、以及评测闭环，能嵌进业务系统，代价是开发和维护成本。按场景讲差异，不要贬低 Dify。

3. 日常八股
1) 部署大模型用的什么推理框架
> 答：主力 vLLM（PagedAttention + 连续批处理，生态和模型覆盖最全）；多轮/强共享前缀、结构化输出场景用 SGLang（RadixAttention 前缀复用）；追求单机极致性能用 TensorRT-LLM；验证与边缘端用 Ollama / llama.cpp。

2) 部署的参数量多大的模型
> 答：7B～32B 为主，如 Qwen2.5-7B/14B、Qwen-VL 系列；在线服务常用 AWQ/GPTQ 量化到 4bit 压显存。要能说清"为什么这个规模"——显存 = 权重 + KV Cache，7B/4bit 约 4~5G，14B 约 9G，再按并发和上下文长度留 KV 余量。

3) 使用的显卡类型
> 答：7B 级别单卡 4090 24G 够用；14B 以上、要高并发或长上下文用 A100 80G / L20 / H20。被追问就讲显存账和并发上限，别只报型号。

4) MOE专家混合模型的概念
> 答：把 FFN 拆成多个"专家"，用一个门控网络对每个 token 只选 Top-k 个专家（如 k=2）参与计算再按权重加权求和。好处是总参数量做大但单 token 计算量基本不变（稀疏激活）；代价是显存占用大，需要专家并行，且要做负载均衡防止专家塌缩。

5) transformer结构简述下
> 答：每层 = 多头自注意力（建模 token 之间的关系）+ 前馈网络 FFN（逐位置非线性变换），外面套残差连接和 LayerNorm，输入加位置编码。Encoder 双向注意力，Decoder 额外有因果掩码自注意力与交叉注意力；现在的大模型基本是 Decoder-only，靠因果掩码做 next-token 预测。

6) vLLM和SGlang推理框架的区别
> 答：核心机制不同。vLLM 是 PagedAttention——把 KV Cache 按块分页管理，显存利用率从约 20% 提到 90%+，配合连续批处理提升吞吐；SGLang 是 RadixAttention——用前缀树复用公共前缀的 KV，多轮对话、共享 system prompt、Agent 结构化输出场景前缀命中率高，吞吐更好。选型上：要生态成熟、模型覆盖广用 vLLM；要前缀复用、结构化约束用 SGLang。

7) AI Coding的交互方式
> 答：三档——行内补全（写的时候自动续）、对话问答（问 API、问报错）、Agent 模式（读写文件、跑测试、多轮自主迭代）。实际用法是先对齐方案再让它写代码，不是一句话丢需求。

8) AI Coding的过程中和大模型的哪个结构有关呢
> 答：主要是 Decoder 的自回归生成和多头注意力：每步基于已生成 token 的注意力（KV Cache）预测下一个 token；上下文窗口决定能看到多少代码，注意力的长程建模决定跨文件理解；再叠加代码词表和代码语料的训练。本质是"下一个 token 预测"在代码分布上的能力。
