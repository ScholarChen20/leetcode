## 具身智能AI应用

### 自我介绍
> （略）30 秒：学校/专业 + 一段与岗位最相关的项目（负责哪块、量化结果）+ 技术栈关键词 + 投递理由。

### 项目/实习经历
1) 挑一个项目介绍下遇到的问题，你的解决策略，具体的技术设计
> 答：按"问题 → 技术设计 → 结果"讲，技术设计要能拆到模块。示范：多轮 Agent 效果衰减。技术设计分三层——①上下文层：工具结果按 schema 裁剪、超过 N 轮的做滚动摘要、关键事实抽成结构化 KV 不占窗口；②编排层：按节点边界裁剪而不是按轮次裁，避免半截任务被切断；③验证层：每轮结束做一次"目标是否已满足"的判定，满足就提前终止。结果：token 降约 60%，任务完成率不降反升。

2) 业务指标是怎么计算出来的
> 答：先说清四要素——指标定义（分子/分母）、数据来源（埋点/日志/DB）、统计周期、排重口径。例：自动处理率 = 自动闭环工单数 / 总工单数（同一天、剔除测试账号与重复单）。再说可信度：优化前后用同一口径对比，能灰度就做 AB 分组，避免把"流量结构变化"当成"方案有效"。

3) Badcase闭环流程详细介绍下
> 答：五步——发现（线上监控、用户反馈、评测集跑挂）→ 归因（分层定位：检索没召回？prompt 没约束住？工具报错？模型能力不足？）→ 修复（对应改分块、改 prompt、加规则校验、换模型或加工具）→ 回归（这条 case 必须入评测集，跑全量防退化）→ 上线（灰度放量 + 指标监控，不达标回滚）。核心原则：每条 badcase 都要变成一条回归用例，否则同一个坑会踩第二次。

4) 如果智能体内容报错，如何保证健全的运行体系（例如工具调用失败等）
> 答：六件套——①超时 + 指数退避重试（区分可重试与不可重试错误）；②熔断降级（工具挂了走备用实现，或直接告知用户"这项能力暂不可用"）；③幂等（写操作带唯一键，防重试导致重复下单/重复建单）；④schema 校验 + 参数默认值兜底；⑤最大步数与预算限制 + 状态机保证流程可恢复、可人工接管；⑥可观测（全链路 trace、错误分类统计、告警）。

5) AI时代最重要的能力是什么
> 答：定义问题 + 判断力 + 系统设计。AI 把"写"的成本打下来之后，稀缺的是知道该做什么、怎么判断结果好坏、怎么把零件拼成能上线的系统。

6) 你在AI Coding过程中的交互方式（什么东西会交给AI）
> 答：三档分工——①全交：样板代码（CRUD、DTO、单测、正则、SQL、脚本）；②交接初稿自己改：有明确规格的逻辑实现、重构、写文档；③自己写、AI 只做 review：架构决策、核心链路、涉及资金与安全的代码。交互上是先对齐方案再让它写，给上下文和约束，写完自己必读 diff。

### 场景问答
1) 机器人动作执行的全流程
> 答：感知（相机/点云/力觉）→ 状态估计与场景理解（检测、位姿、建图）→ 任务规划（做什么，高层序列）→ 运动规划（怎么走，轨迹生成 + 碰撞检测 + 约束）→ 控制执行（关节位置/力矩，力控或阻抗控制）→ 传感器反馈闭环，失败则重规划。分层讲：高层认知、中层规划、底层控制，每层的频率和时延量级不一样。

2) 用户自然语言指令到机器人执行动作的过程是怎么实现的
> 答：语音/文本 → ASR + LLM 解析意图与槽位（目标物、位置、数量、约束）→ 与场景感知对齐，把语言指代绑定到具体物体（这一步最容易错，常用视觉 grounding 或让模型输出候选再校验）→ 拆成技能原语（导航、抓取、放置、开门）→ 参数化并做安全检查（可达性、碰撞、力限）→ 下发执行 → 结果校验，失败回退重规划或请求澄清。关键点：语言到动作之间必须有"指代落地 + 安全校验"两道闸。

3) VLA具身智能了解多少
> 答：Vision-Language-Action，把视觉观测 + 语言指令直接映射成动作（动作 token 或轨迹），端到端训练，代表工作 RT-2、OpenVLA、π0。优势是泛化和指令跟随能力强；难点是动作数据靠遥操作采集、成本高，推理频率要满足实时控制，长时序任务容易累积误差。工程上常见分层方案：VLA 出高层意图/关键点，底层仍交给传统控制器与运动规划执行。
