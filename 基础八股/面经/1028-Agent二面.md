# 常见八股 · 参考答案

> **答题公式**：一句话定位 → 两者目标/信号/数据的对比 → 工程代价 → "我们实际怎么串起来用"。
> 这两道题是**同源题**：SFT 讲清"模仿"，GRPO 讲清"试错"，最后用"冷启动 SFT → RL → 拒绝采样"把两者缝起来，就是满分答法。

## 1. SFT 和 GRPO 的区别

**一句话**：SFT 是**监督模仿**——给定标准答案，逐 token 最大化它的似然；GRPO 是**强化学习**——不给答案，只给奖励，让模型自己采样一批回答、按组内相对好坏调整概率。前者教"**像人一样说**"，后者教"**答对**"。

**① 优化目标对比（写出公式最能体现理解）**

- **SFT**（token 级交叉熵）：
  $$L_{SFT} = -\sum_{t} \log \pi_\theta(y_t \mid x, y_{<t})$$
  每个位置都有"标准下一 token"，是**逐 token 的强监督**。

- **GRPO**（Group Relative Policy Optimization）：
  对同一个 prompt 采样 $G$ 个回答，算各自奖励 $r_i$，用**组内均值和标准差归一化**得到优势：
  $$A_i = \frac{r_i - \text{mean}(r_{1..G})}{\text{std}(r_{1..G})}$$
  $$L_{GRPO} = -\mathbb{E}\Big[\frac{1}{G}\sum_i \frac{1}{|o_i|}\sum_t \min\big(\rho_t A_i,\ \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon)A_i\big) - \beta \, D_{KL}(\pi_\theta \| \pi_{ref})\Big]$$
  其中 $\rho_t = \pi_\theta(o_t)/\pi_{\theta_{old}}(o_t)$。
  **关键：不需要 critic/value 模型**——PPO 要单独训一个价值网络估 baseline，GRPO 直接用"同组其他回答的平均分"当 baseline，省掉与策略等大的模型，显存和算力省一大截（这是 DeepSeek 用它做 R1 的核心原因）。

**② 五个维度对比**

| 维度 | SFT | GRPO |
|---|---|---|
| 监督信号 | **token 级**、稠密、来自标注答案 | **序列级**、稀疏、来自奖励函数/规则校验 |
| 数据要求 | 需要 `(prompt, 标准回答)` 配对，贵在**标注** | 只需 prompt + **可自动判分的奖励**（数学对答案、代码跑单测、格式校验） |
| 学到什么 | 格式、风格、指令跟随、领域表达 | 推理策略、自我纠错、探索出数据里没有的解法 |
| 上限 | **受限于标注数据的天花板**，只能模仿 | 可以超越示范数据（R1-Zero 纯 RL 就涌现出长 CoT 和"aha moment"） |
| 风险 | 过拟合模板、记住错误答案、灾难性遗忘 | **奖励黑客**（刷格式骗分）、训练不稳、长度膨胀、需要大 batch × 多次采样 |
| 代价 | 便宜、稳定、一次前反向 | 贵：每步要采样 G 条完整回答 + 参考模型前向（算 KL） |

**③ 为什么不能只用其中一个**
- 只有 SFT：模型只会复述见过的解法，遇到新题不会探索，也无法从"答错"里学习；
- 只有 RL：冷启动太差时采样空间里几乎没有正样本，奖励全是 0，梯度消失（R1-Zero 也遇到了可读性差、中英混杂的问题，所以 R1 加了冷启动 SFT）。

**④ 实际链路（一句话收尾，最能加分）**
> 典型三段式：**SFT 冷启动**（学会格式和基本推理）→ **GRPO/PPO 强化**（用可验证奖励提升正确率）→ **拒绝采样 + 再 SFT**（把 RL 采到的高分轨迹固化成新数据，迭代）。LoRA/全参都可能，RL 阶段通常要 reference model 算 KL 防跑偏。

**追问预案**
- **和 DPO 的区别？** DPO 用**离线偏好对** `(chosen, rejected)` 做分类式损失，不需要采样和奖励模型，稳但**没有在线探索**，容易对偏好数据过拟合；GRPO 是 on-policy，靠采样探索。
- **KL 项为什么必须有？** 约束新策略别离参考模型太远，防止为了刷奖励把语言能力训崩（reward hacking 的语言层面表现就是胡言乱语）。
- **$G$ 取多大？** 一般 8~64，太小 baseline 噪声大，太大显存吃不住（G 条序列要同时前向）。

## 2. SFT 原理

**一句话**：SFT 就是在**预训练好的模型上，用 `(指令, 回答)` 数据继续做自回归语言建模**，把"通用文本续写"的能力对齐到"按指令回答"的分布上。

**① 数学本质：带 mask 的最大似然**
$$\theta^* = \arg\max_\theta \sum_{(x,y)\in D} \sum_{t=1}^{|y|} \log \pi_\theta(y_t \mid x, y_{<t})$$
实操里 **loss 只算 response 部分，prompt 部分置 -100 屏蔽**（`labels[prompt_len:] = token_ids`），否则模型会去学"怎么提问"，浪费容量还降低效果。

**② 训练机制**
- **Teacher forcing**：每个位置喂的都是**真实的前一个 token**（不是自己上一步的输出），所以可以整句并行算 loss，一次前向就拿到所有位置的梯度；
- 但推理是自回归的、喂的是自己的输出 → 训练/推理分布不一致，即 **exposure bias**：训练时从没犯过错，推理时一旦错了就会累积（这也是 RL/DPO 想解决的动机之一）；
- **全参微调**：更新所有参数，效果上限高，但显存 ≈ 参数 + 梯度 + 优化器状态（Adam 混合精度约 **16 字节/参数**），7B 就要 100G+，靠 ZeRO / FSDP 切分；
- **LoRA**：冻结 $W$，只训低秩增量 $\Delta W = BA$（$B\in\mathbb{R}^{d\times r}, A\in\mathbb{R}^{r\times k}$，$r$ 取 8~64），可训练参数降到 0.1%~1%；推理时可把 $BA$ 合并回 $W$，**不增加延迟**；作用在 q/k/v/o 和 MLP 上效果最好；
- **QLoRA**：基座量化成 **4bit NF4** + 双重量化 + paged optimizer，单卡 24G 就能微 7B。

**③ 数据工程（真正的胜负手，比调参重要十倍）**
- **质量 > 数量**：LIMA 证明 1000 条高质量数据就能显著对齐；
- **多样性**：任务类型、长度、难度都要铺开，否则只会一种腔调；
- **去重 + 去污染**：和评测集重叠会虚高（数据泄漏）；
- **格式统一**：严格按模型的 **chat template** 拼 special token，格式错了模型会学歪；
- **混入通用数据**（10%~30%）缓解**灾难性遗忘**。

**④ 关键超参**
lr（全参 1e-5~2e-5，LoRA 1e-4~2e-4）> 数据质量 > epoch（**1~3 轮，多了必过拟合**）> batch（用梯度累积凑）> warmup + cosine 衰减；工程上用 bf16、FlashAttention、sequence packing（把多条短样本拼成一条，避免 padding 浪费，注意 attention 要 block-diagonal）。

**⑤ 三大坑**
1. **灾难性遗忘**：只训垂域数据，通用能力掉 → 混通用数据、LoRA 而非全参、早停；
2. **幻觉被放大**：标注里的事实错误会被模型学成"自信地胡说" → 数据要人工/模型交叉校验；
3. **loss 降了但效果差**：训练 loss 只反映"像不像标注"，不反映"对不对"，必须用**held-out 集 + LLM-as-judge/人工盲评**看真实能力。

**⑥ 一句话边界（被追问"什么时候不该用 SFT"就答这个）**
> SFT 教的是**格式、风格、任务范式**，不是**新知识**也不是**新推理能力**。要灌知识用 **RAG**，要提升推理正确率用 **RL（GRPO/PPO）**，要调偏好用 **DPO**。很多团队 SFT 训不出来，本质是拿 SFT 去干 RAG 的活。
