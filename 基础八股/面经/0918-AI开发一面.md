### 基础八股
1) 堆和栈的区别 
> 栈主要保存函数调用过程中的临时数据，由系统自动管理，速度快但空间有限；堆主要保存动态创建的数据，由程序或垃圾回收器管理，空间较大但管理复杂，可能发生泄漏和碎片化。）
2) 如何维护堆
> 操作系统通过虚拟内存、页表和物理页来维护堆的底层空间
3) Java中的垃圾回收检测算法
> 可达性分析算法:通过一系列的称为 “GC Roots” 的对象作为起点，从这些节点开始向下搜索，节点所走过的路径称为引用链，当一个对象到 GC Roots 没有任何引用链相连的话，则证明此对象是不可用的，需要被回收。
4) 如果检测无引用的对象，是否可以判断是可回收的垃圾
5) 哈希表结构介绍下（数组 + 哈希函数 + 冲突处理机制）
6) 哈希表扩容机制
>当负载因子超过阈值时，哈希表通常会扩容： 1.创建更大的数组； 2.重新计算每个 key 的位置； 3。将所有数据迁移到新数组中
7) 如何减少哈希冲突（链地址法：存链表/红黑树；开放地址法：线性探测、二次探测、双重哈希）
8) 对象可以被回收，就代表一定会被回收吗？
> Java 对象变得不可达，只能说明它具备被垃圾回收的条件，并不代表一定会立即或最终被回收。垃圾回收由 JVM 根据内存压力和垃圾回收器策略决定，System.gc() 也只是建议。特别是在 JVM 退出前，某些对象可能一直没有经历 GC。因此，Java 程序不能依赖对象被回收来执行关键资源释放逻辑。
9) 哪些对象可以作为 GC Roots 呢？
> 虚拟机栈（栈帧中的局部变量表）中引用的对象 ;本地方法栈（Native 方法）中引用的对象 ;方法区中类静态属性引用的对象 ;方法区中常量引用的对象 ;所有被同步锁持有的对象 ;JNI（Java Native Interface）引用的对象
10) 垃圾收集算法
> 标记-清除（Mark-and-Sweep

> 标记-复制：可以将内存分为大小相同的两块，每次使用其中的一块。当这一块的内存使用完后，就将还存活的对象复制到另一块去，然后再把使用的空间一次清理掉

> 分代垃圾收集器会根据对象存活周期的不同将内存分为几块。一般将 Java 堆分为新生代和老年代，这样可以根据各个年代的特点选择合适的垃圾收集算法。

11) 垃圾收集器
> G1 (Garbage-First) 是一款面向服务器的垃圾收集器，主要针对配备多颗处理器及大容量内存的机器. 以极高概率满足 GC 停顿时间要求的同时，还具备高吞吐量性能特征。
G1 收集器在后台维护了一个优先列表，每次根据允许的收集时间，优先选择回收价值最大的 Region
