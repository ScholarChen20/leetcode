### 基础八股
1) 堆和栈的区别 
> 栈主要保存函数调用过程中的临时数据，由系统自动管理，速度快但空间有限；堆主要保存动态创建的数据，由程序或垃圾回收器管理，空间较大但管理复杂，可能发生泄漏和碎片化。）
> 补充一句防坑：这里说的是**内存的堆栈**，不是数据结构里的"堆"（优先队列），面试官问"如何维护堆"时通常是顺着内存这条线问，先确认一句再答。
2) 如何维护堆
> 操作系统通过虚拟内存、页表和物理页来维护堆的底层空间
> 再补实现层：用户态由分配器（ptmalloc/tcmalloc）管理，维护空闲块链表与大小分级（bin），小块从 bin 里找合适块切分，释放时与相邻空闲块合并减少碎片，大块走 mmap、超大块直接归还内核；扩容靠 brk/mmap 向内核要新的虚拟内存。
3) Java中的垃圾回收检测算法
> 可达性分析算法:通过一系列的称为 “GC Roots” 的对象作为起点，从这些节点开始向下搜索，节点所走过的路径称为引用链，当一个对象到 GC Roots 没有任何引用链相连的话，则证明此对象是不可用的，需要被回收。
4) 如果检测无引用的对象，是否可以判断是可回收的垃圾
> 答：不能直接判定。不可达只是"具备回收条件"，还要看引用类型（强/软/弱/虚引用的回收时机不同）、对象是否在 finalize 里被复活、以及 GC 是否真的发生（时机由 JVM 按内存压力决定，System.gc() 只是建议）。所以"可回收"是必要条件，不是充分条件。
5) 哈希表结构介绍下（数组 + 哈希函数 + 冲突处理机制）
> 答：数组存桶，哈希函数把 key 映射成下标，冲突用链地址法（链表，过长转红黑树）或开放寻址法（线性/二次探测、双哈希）解决。平均 O(1)，最坏退化为 O(n)。要点：哈希函数要扰动充分（如 h ^ (h >>> 16)）以降低碰撞，容量取 2 的幂便于位运算取模。
6) 哈希表扩容机制
>当负载因子超过阈值时，哈希表通常会扩容： 1.创建更大的数组； 2.重新计算每个 key 的位置； 3。将所有数据迁移到新数组中
> 补充 Java 8 的优化：扩容为原容量 2 倍，元素新下标只可能是"原位置"或"原位置 + 旧容量"，用高低位链表拆分，避免逐个重算 hash；树化节点在拆分后可能退化为链表。
7) 如何减少哈希冲突（链地址法：存链表/红黑树；开放地址法：线性探测、二次探测、双重哈希）
> 答：四个手段——好的哈希函数（充分扰动、分布均匀）、合理的初始容量与负载因子（0.75 是时间与空间的折中）、冲突处理策略（链地址法允许超过 1 的负载因子，开放寻址法必须留空位）、及时扩容。另外 key 的 equals/hashCode 必须一致，否则会出现"存进去取不出来"。
8) 对象可以被回收，就代表一定会被回收吗？
> Java 对象变得不可达，只能说明它具备被垃圾回收的条件，并不代表一定会立即或最终被回收。垃圾回收由 JVM 根据内存压力和垃圾回收器策略决定，System.gc() 也只是建议。特别是在 JVM 退出前，某些对象可能一直没有经历 GC。因此，Java 程序不能依赖对象被回收来执行关键资源释放逻辑。
9) 哪些对象可以作为 GC Roots 呢？
> 虚拟机栈（栈帧中的局部变量表）中引用的对象 ;本地方法栈（Native 方法）中引用的对象 ;方法区中类静态属性引用的对象 ;方法区中常量引用的对象 ;所有被同步锁持有的对象 ;JNI（Java Native Interface）引用的对象
10) 垃圾收集算法
> 标记-清除（Mark-and-Sweep
> 标记-复制：可以将内存分为大小相同的两块，每次使用其中的一块。当这一块的内存使用完后，就将还存活的对象复制到另一块去，然后再把使用的空间一次清理掉

> 分代垃圾收集器会根据对象存活周期的不同将内存分为几块。一般将 Java 堆分为新生代和老年代，这样可以根据各个年代的特点选择合适的垃圾收集算法。

> 补全被截断的部分：标记-清除 = 标记可达对象再统一清除，实现简单但产生内存碎片；标记-整理 = 标记后把存活对象向一端移动再清理边界外内存，无碎片但移动成本高，适合老年代；分代收集 = 新生代对象朝生夕死用复制算法（Eden + 两个 Survivor），老年代存活率高用标记-整理或标记-清除。
11) 垃圾收集器
> G1 (Garbage-First) 是一款面向服务器的垃圾收集器，主要针对配备多颗处理器及大容量内存的机器. 以极高概率满足 GC 停顿时间要求的同时，还具备高吞吐量性能特征。
G1 收集器在后台维护了一个优先列表，每次根据允许的收集时间，优先选择回收价值最大的 Region
> 再横向对比一句：Serial/ParNew/Parallel 是分代 + 停顿式；CMS 主打低停顿但有碎片和并发失败风险；G1 按 Region 划分、可预测停顿；ZGC 用染色指针做并发标记整理，停顿在亚毫秒级，适合大堆低延迟场景。

### 手撕
给定一个二叉树的根节点 root ，和一个整数 targetSum ，求该二叉树里节点值之和等于 targetSum 的最小路径的长度
> 答：前缀和 + DFS + 哈希表。维护 map[前缀和] = 该前缀和**最早出现的深度**（深度最小 ⇒ 路径最短），进入节点时 cur = pre + node.val，查 cur - targetSum 是否在 map 中，命中则用 depth - map[cur-targetSum] 更新答案；再记录 cur→depth（只记首次）、递归子树、回溯时删除。时间 O(n)，空间 O(树高)。
>
> ```python
> def minPathLen(root, targetSum: int) -> int:
>     best = float('inf')
>     pre = {0: 0}                      # 前缀和 -> 最早出现的深度
>
>     def dfs(node, cur_sum, depth):
>         nonlocal best
>         if not node:
>             return
>         cur = cur_sum + node.val
>         if cur - targetSum in pre:
>             best = min(best, depth - pre[cur - targetSum])
>         if cur not in pre:            # 只记录最早（最浅）的一次
>             pre[cur] = depth
>             need_del = True
>         else:
>             need_del = False
>         dfs(node.left, cur, depth + 1)
>         dfs(node.right, cur, depth + 1)
>         if need_del:
>             del pre[cur]              # 回溯，保证 map 只含当前路径
>
>     dfs(root, 0, 1)
>     return 0 if best == float('inf') else best
> ```
>
> 易错点：①回溯必须删掉本次新增的键，否则会串到兄弟子树；②只删"本次新插入"的键（need_del），否则会误删更浅层的同值前缀；③深度从 1 开始计数，答案即深度差。
