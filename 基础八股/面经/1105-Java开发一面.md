### 常见八股

#### 1. 行锁和表锁区别
> 表锁锁整张表，行锁只锁一行。表锁加锁快、开销小、不会死锁，但并发度低；行锁开销大、加锁慢、可能死锁，但并发度高。MyISAM 只支持表锁，InnoDB 都支持、默认用行锁；而且 InnoDB 的行锁是加在索引上的，SQL 不走索引就会把扫描到的行全锁住，效果接近锁表。

#### 2. 记录锁、间隙锁和临键锁区别
> 记录锁锁单条索引记录；间隙锁锁记录之间的空隙，是开区间如 (5,10)，只阻止插入；临键锁是两者组合，锁左开右闭区间如 (5,10]，也是 InnoDB 在可重复读下的默认加锁单位，目的是防幻读，RC 下不加间隙锁。另外间隙锁之间互不冲突，只有插入意向锁会和它冲突；唯一索引等值查询时临键锁会退化成记录锁。

#### 3. MySQL 的死锁
> 死锁是两个事务互相持有对方需要的锁，形成循环等待，常见于加锁顺序不一致、间隙锁与插入冲突、大事务长持锁。InnoDB 用等待图检测，发现死锁就回滚代价小的事务并报 1213。避免的办法是统一加锁顺序、缩短事务、让 SQL 走索引，必要时降到 RC 或把热点行串行化；业务侧重试要保证幂等。

#### 4. 共享锁和排他锁区别
> S 锁是共享锁、读锁，用 `SELECT ... FOR SHARE`（旧写法 `LOCK IN SHARE MODE`）显式加；X 锁是排他锁、写锁，`SELECT ... FOR UPDATE` 和 insert/update/delete 自动加。多个事务可以同时持有同一行的 S 锁，但 S 与 X 互斥、X 与 X 也互斥，所以一个事务加了 X 锁，其他事务读写都要等。另外普通 SELECT 是快照读，靠 MVCC 不加锁，只有当前读才需要加 S/X 锁。

#### 5. 慢 SQL 如何优化
> 先开慢查询日志找出慢 SQL，再用 EXPLAIN 看执行计划，重点看 type 是不是 ALL、有没有走索引、扫描行数 rows，以及有没有 Using filesort 和 Using temporary。然后按优先级处理：建合适的联合索引（最左前缀）、避免索引失效（列上做函数、隐式类型转换、前导模糊查询）、去掉 `SELECT *`、深分页改成游标或延迟关联。数据量太大再考虑读写分离、加缓存、分库分表，最后用 EXPLAIN 和压测确认效果。
