### 实习经历
1) 广告投放智能体业务背景，你负责的部分，有什么好的效果
> 答：背景讲"痛点 + 链路"：投放链路上素材生产、人群圈选、建计划、出价调整、数据复盘高度依赖人工，重复量大且经验难沉淀。我负责的部分要说得具体（编排逻辑 / 素材生成链路 / 数据回收），不负责的部分也坦白。效果给三个量化：单条计划搭建时长（分钟级→秒级）、素材产能（倍数）、人工干预率或采纳率。数字必须是真实能撑住追问的。

2) 素材生成使用的是什么模型（Seedream5.0 seedance2.0)
> 答：文生图用 Seedream 5.0，图生视频用 Seedance 2.0。选型理由按四维说：①出图/出片质量与风格一致性（能不能守住品牌调性）；②可控性（是否支持参考图、局部重绘、首尾帧控制）；③成本与时延（单张/单条成本、并发配额）；④合规（商用授权、内容安全审核）。工程上做的是"模板化 prompt + 批量生成 + 人工挑图 + 高复用素材缓存"，而不是每次从零生成。

3) 投放智能体你实现的功能的技术思路，平台定位是啥
> 答：技术思路——Workflow 编排做主干（素材生成 → 文案生成 → 计划搭建 → 数据回收），在决策点（选人群、定出价）用 LLM + 规则做判断，工具层封装投放平台 API，外层加超时重试、幂等（防止重复建计划）、人工确认节点。平台定位说清"给谁用、替代掉什么"：面向投放运营的自助式工具，把重复劳动自动化，人从执行者变成审核者。

4) 网络检测助手工作流流程
> 答：输入系统名或 IP → 解析出 IP（域名解析/资产表查询）→ 双端连通性 Ping 检测 + 磁盘水位检测（可并行）→ 结果判定（正常 / 可自动修复 / 需人工）→ 自动修复或直接转工单 → 记录结果与耗时。补充两个设计点：检测阶段只读、修复阶段走白名单 + 审批；每步都有超时，避免卡在某一步。

5) 修复是在生产环境上实现吗
> 答：不是无条件直连。分级策略：只读探测（Ping、读水位）可以直接连；写操作走白名单动作集（重启服务、清理临时文件、扩容等）+ 审批或双人确认，执行前做快照、执行后验证结果；全程留操作日志，失败自动转人工工单，支持回滚。跨网段或高风险场景先灰度到单台再加量。

### 科研/项目经历
> 这三题是你自己的论文内容，下面给的是**讲法骨架**，细节一定要换成你的真实设计。

1. ominirad网络模型架构
> 答：四段式讲：①输入与编码（视觉主干 + 文本/条件编码器，各自输出什么维度的特征）；②跨模态交互（用什么融合方式：cross-attention / 特征拼接 / 对比对齐，在哪一层融合，为什么不在更早或更晚）；③任务头（各任务分支怎么设计，共享什么、解耦什么）；④训练目标（损失函数组合、各任务权重怎么定）。最后必须补一句"这个设计解决了什么缺陷"——面试官真正想听的是动机。**提前把架构图手画熟练，这题大概率让你画。**

2. 如何区分不同视觉任务的
> 答：两条路径要说清你用哪条：①显式路由——用任务指令/任务 ID 作为条件输入，走对应的任务头或 prompt，主干共享、分支解耦；②隐式统一——把所有任务统一成"条件生成/条件预测"的形式，让模型根据条件自行切换行为。工程上一般选显式路由，因为可控、可单独调优、出问题好定位。

3. 视觉智能体整个流程
> 答：任务理解与分解（把问题拆成"要看什么、要量什么"）→ 工具选择与调用（检测、分割、OCR、深度估计、检索）→ 中间结果结构化（框、掩码、文本、数值统一成 JSON）→ 交叉验证与反思（多工具结果不一致就重查或换工具）→ 汇总输出（带证据和置信度）。关键点：视觉工具的输出必须是结构化的，否则模型没法可靠推理。
