## AI Agent

### 自我介绍
> （略）30 秒：学校/专业 + 最相关的智能体项目（负责哪块、量化结果）+ 技术栈关键词 + 投递理由。

### 项目/实习经历
1) 实习经历/项目经历的收获
> 答：三点收口——①工程认知从"能跑"变成"可控、可测、可运维"（加了状态机、超时、幂等之后系统才敢上生产）；②学会用指标说话（badcase 回流、改前改后对比）；③推动跨团队落地的沟通方式。挑一点配一个具体例子。

2) 手画你搭建的智能体框架
> 答：五层——接入层（API/会话/鉴权）、编排层（Router 选 ReAct / Plan / Workflow，状态机驱动、可中断恢复）、能力层（工具注册中心、Skill 渐进加载、RAG）、模型层（LLM 网关、多模型路由、限流计费）、支撑层（记忆、上下文压缩、日志埋点、评测）。画完顺着讲一次请求怎么流过去：用户输入 → 意图识别选模式 → 编排器调度 → 模型决策调工具 → 结果校验 → 汇总返回 → 落日志。

3) 你认为智能体具备有哪些能力
> 答：感知理解、规划（拆解与动态调整）、工具调用、记忆（短期上下文 + 长期偏好知识）、反思纠错（校验、重试、换策略）、安全可控（权限边界、高危动作人工确认）。补一句"前四个是能力，后两个是能不能上生产"。

4) 你了解的智能体框架的一个历程
> 答：按技术形态讲演进——①Prompt 工程 + 纯文本 CoT（只有思考没有行动）；②ReAct / Toolformer 让模型能调工具，形成"思考-行动-观察"循环；③AutoGPT / BabyAGI 式自主循环，暴露了跑偏和死循环问题；④编排框架（LangChain/LangGraph、AutoGen、Dify）用 DAG 与状态机把流程管住，多 Agent 协作落地；⑤平台化：MCP 统一工具接入、Skill 封装领域能力、加上评测与可观测。主线是从"更自主"转向"更可控、可测、可运维"。

5) Agent的发展历程
> 答：同上主线，再补两侧变化：模型侧从"靠 prompt 硬凑格式"到原生 Function Call 与结构化输出、再到推理模型带来更强的规划能力；工程侧从脚本拼装到有状态编排、分级记忆、成本与延迟治理。结论：Agent 的瓶颈从"模型聪不聪明"逐渐移到"工程做得稳不稳"。

### 性格/工作/家庭
1) 能不能接受加班
> 答：接受项目冲刺期的合理加班，同时会复盘是排期估错还是方案有坑——能靠方案优化的不靠熬时间解决。举个真实例子（版本上线前一周的加班安排）。

2) 半导体行业了解多少
> 答：按投递公司准备：产业链（设计—制造—封测—设备材料）、公司在链条里的位置、行业的周期性与国产替代逻辑。不确定的说法是"我了解到 A 和 B，更细的部分想请教"，别硬编。

3) 业务爱好
> 答：说一个能体现持续性和专注度的（长跑、开源、写技术笔记），并自然带出"所以我能坚持做长期的事"。

4) 工作上做事方法/性格
> 答：三点——沟通前置（动手前先对齐目标与验收）、过程留痕（方案和结论写文档）、对结果负责（不把问题往下游推）。

5) 如何处理工作上一些疑难问题
> 答：先自查（日志、文档、最小复现），给自己设时限（1~2 小时），超时就带着"已排除的可能 + 我的假设 + 需要谁配合"去求助，而不是空手问"这怎么办"。解决后补一条记录进团队知识库。

6) 工作上的性格态度
> 答：对事较真、对人配合——技术问题拿数据争，结论定了就执行；接受被推翻，但要给出理由。

7) 处理非熟悉领域的业务背景，如何保证自己能快速熟悉
> 答：三步：①找权威入口（官方文档/架构文档 + 找老同事 30 分钟对齐全局，比自学三天快）；②画出主线链路和数据流，标出自己负责的节点与上下游；③做最小可运行 demo 验证理解，再回头补细节。原则是"先跑通再深挖"。
