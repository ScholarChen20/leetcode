## 一、GPU 集群

### Q1. GPU 主要看哪些指标？

**参考回答：**

主要看三项：**计算能力、显存容量、显存带宽**。训练更关注算力和通信，LLM Decode 更容易受显存带宽限制，长上下文和高并发主要受 KV Cache 显存限制。

### Q2. NVLink、PCIe、InfiniBand、RDMA 分别是什么？

**参考回答：**

- `PCIe`：CPU 和 GPU、GPU 和 GPU 的通用总线，带宽相对低。
- `NVLink/NVSwitch`：机器内部 GPU 高速互联，适合张量并行。
- `InfiniBand`：机器之间的高速网络。
- `RDMA`：绕过 CPU 和操作系统内核，直接访问远端内存，降低通信延迟。

简单说：**机内优先 NVLink，跨机通常使用 InfiniBand/RDMA。**

### Q3. NCCL 是什么？训练任务卡住怎么排查？

**参考回答：**

NCCL 是 NVIDIA 的集合通信库，负责 `AllReduce`、`AllGather` 等多卡通信。任务卡住时，我会先看 `NCCL_DEBUG` 日志，再检查各进程是否进入了相同的通信操作、GPU 是否掉卡、网络和显存是否正常，最后检查拓扑和超时配置。

最常见原因是：**某个进程异常退出，或者不同进程走了不同代码分支。**

### Q4. GPU 集群如何调度？

**参考回答：**

训练集群一般使用 `Slurm`，云原生环境常用 `Kubernetes + Volcano`。调度时要考虑 GPU 数量、显存、NVLink/IB 拓扑、任务优先级、配额和故障重调度，避免 GPU 碎片和跨机通信开销过大。

## 二、分布式训练

### Q5. DP、DDP、TP、PP、EP、ZeRO 有什么区别？

| 技术 | 主要切分对象 | 适用场景 |
|---|---|---|
| DP/DDP | 数据 | 模型单卡能放下的常规训练 |
| TP | 参数矩阵/注意力头 | 单层模型太大，多卡协同计算 |
| PP | 模型层 | 模型整体太大，按层切到不同 GPU |
| EP | MoE 专家 | 专家模型 |
| ZeRO/FSDP | 参数、梯度、优化器状态 | 节省训练显存 |

**一句话：** `DP` 解决数据并行，`TP/PP` 解决模型太大，`ZeRO/FSDP` 解决训练状态占显存。

### Q6. DDP 和 DataParallel 有什么区别？

**参考回答：**

`DataParallel` 是单进程多线程，主卡负责分发数据和汇总，容易出现主卡瓶颈。`DDP` 是一张 GPU 对应一个进程，各卡独立计算，再用 `AllReduce` 同步梯度，性能和稳定性更好，生产训练通常使用 DDP。

### Q7. 什么是 3D 并行？

**参考回答：**

3D 并行就是 `DP + TP + PP` 的组合：`TP` 切矩阵，`PP` 切模型层，`DP` 复制并行处理不同数据。通常把通信量大的 TP 放在机内 NVLink，把 DP 或 PP 放到跨机网络。

### Q8. ZeRO-1、ZeRO-2、ZeRO-3 有什么区别？

**参考回答：**

- `ZeRO-1`：切分优化器状态。
- `ZeRO-2`：在此基础上切分梯度。
- `ZeRO-3`：继续切分模型参数，计算时临时聚合。

级别越高，显存越省，但通信和实现复杂度也越高。`DeepSpeed ZeRO` 和 `PyTorch FSDP` 都是常见方案。

### Q9. 训练显存怎么估算？

**参考回答：**

训练显存主要由**权重、梯度、优化器状态、激活和通信缓冲**组成。FP16 加 Adam 时，模型状态通常按每个参数约 12～16 字节粗略估算，激活还与 batch、序列长度、层数有关；显存不够时可以使用 ZeRO、FSDP、梯度累积和激活重计算。

### Q10. TP 是怎么切分的？

**参考回答：**

TP 通常把线性层按列或按行切分，把 Attention 按 head 切分。每张卡只计算一部分，最后通过 `AllReduce` 或 `AllGather` 合并结果。因为每层都可能通信，所以 TP 更适合放在 NVLink 高速互联的 GPU 之间。

### Q11. PP 有什么问题？如何减少流水线气泡？

**参考回答：**

PP 按模型层切分成多个 stage，再把一个 batch 切成多个 micro-batch 流水执行。主要问题是流水线气泡，可以增加 micro-batch 数量，或使用 `1F1B`、`Interleaved 1F1B` 减少空闲时间。

### Q12. FP16 和 BF16 怎么选？

**参考回答：**

`FP16` 精度和显存较好，但动态范围小，可能需要 loss scaling。`BF16` 动态范围接近 FP32，训练更稳定，A100/H100 等新 GPU 通常优先使用 BF16。

### Q13. 梯度累积解决什么问题？

**参考回答：**

显存放不下大 batch 时，用多个小 batch 累积梯度，累积到指定次数后再更新一次参数。有效全局 batch 大小是：

```text
global_batch = micro_batch × 累积步数 × DP 卡数
```

### Q14. 训练出现 NaN 或 loss 不收敛，怎么排查？

**参考回答：**

我会按这个顺序排查：数据是否异常、学习率是否过大、是否缺少 warmup、FP16 是否溢出、梯度是否爆炸、模型初始化是否异常。常用处理是清洗数据、降低学习率、改用 BF16、梯度裁剪和检查坏 batch。

### Q15. 断点续训要保存什么？

**参考回答：**

不仅要保存模型权重，还要保存优化器状态、学习率调度器、当前 step、数据采样进度和随机数状态。这样恢复后训练轨迹才基本连续，还要保留多个 checkpoint，防止最新文件损坏。

### Q16. Verl 训练管线中分布式如何使用？

**参考回答：**

Verl 负责组织训练、采样和奖励计算，训练侧可以使用 FSDP 或 Megatron，rollout 侧使用 vLLM 等推理引擎。我的回答重点会说清楚三点：**训练并行方式、rollout 部署方式、训练权重如何同步。**

如果使用 GRPO，可以省掉 Critic 模型，相比 PPO 显存压力更小。

## 三、模型 Serving

### Q17. 模型 Serving 主要看哪些指标？

**参考回答：**

主要看：`TTFT`（首 Token 延迟）、`TPOT/ITL`（单 Token 延迟）、总延迟、吞吐量、并发数、GPU 利用率、显存占用和错误率。在线业务优先看延迟和稳定性，离线任务优先看吞吐和成本。

### Q18. vLLM 为什么比普通 Transformers 推理快？

**参考回答：**

主要有三点：

1. `PagedAttention` 分页管理 KV Cache，减少显存碎片；
2. 连续批处理，让请求动态进入和退出 batch；
3. 使用更高效的 CUDA Kernel、Prefix Cache 和量化能力。

### Q19. 静态批处理和连续批处理有什么区别？

**参考回答：**

静态批处理要等一批请求凑齐，并且通常要等整批结束。连续批处理按生成过程动态调度，完成的请求立即退出，新请求可以加入，因此高并发下吞吐更高、GPU 利用率更好。

### Q20. Prefill 和 Decode 的区别是什么？

**参考回答：**

`Prefill` 一次处理完整输入，主要是计算密集型；`Decode` 每次生成一个 Token，主要是访存密集型。两者混在一起可能互相影响，所以高性能部署可以做 Prefill-Decode 分离，分别扩缩容和调度。

### Q21. vLLM、SGLang、TensorRT-LLM、Triton 怎么选？

**参考回答：**

- 通用 LLM API：优先 `vLLM`，生态和 OpenAI 兼容接口成熟；
- 多轮、结构化输出、复杂 Agent：可以评估 `SGLang`；
- 固定 NVIDIA 硬件、追求极致性能：使用 `TensorRT-LLM`；
- 多模型、多框架统一托管：使用 `Triton`。

最终要用真实模型和流量压测，不只看框架排名。

### Q22. 模型 Serving 架构怎么设计？

**参考回答：**

基本结构是：网关负责鉴权和限流，调度层负责负载均衡，模型实例负责推理，底层用 GPU 节点运行。生产上还要考虑模型版本、灰度发布、健康检查、自动扩缩容、监控和故障转移。

### Q23. 推理服务如何压测？

**参考回答：**

先固定输入长度、输出长度和请求分布，再逐步增加并发。每档记录 TTFT、TPOT、吞吐、显存、GPU 利用率、排队时间和错误率，找到“吞吐接近峰值且延迟仍满足 SLO”的并发点。

### Q24. 推理服务 OOM 或超时怎么处理？

**参考回答：**

OOM 主要从限制最大上下文、最大并发、最大输出长度和 KV Cache 占用入手，必要时让请求排队或降级。超时要设置客户端和服务端超时，支持流式返回；重试前要确认请求是否幂等，避免重复执行。

## 四、训练与微调

### Q25. 预训练、SFT、RLHF 分别做什么？

**参考回答：**

预训练让模型学习语言和基础知识；SFT 让模型学会遵循指令和业务格式；RLHF、DPO、GRPO 等对齐方法进一步优化回答偏好、任务效果或工具使用行为。

### Q26. LoRA 原理是什么？

**参考回答：**

LoRA 冻结原模型权重，只训练两个低秩矩阵：

```text
W' = W + BA
```

可训练参数和优化器状态都大幅减少，所以显存和训练成本更低。训练完成后可以把 LoRA 合并回原权重，推理时基本没有额外计算开销。

### Q27. QLoRA 和 LoRA 的区别？

**参考回答：**

LoRA 的基座通常保持 FP16/BF16，QLoRA 则把基座进一步量化到 4bit，只训练 LoRA 参数。QLoRA 更省显存，但需要反量化计算，训练速度和精度需要实际评估。

### Q28. 全参微调和 LoRA 怎么选？

**参考回答：**

数据量较大、资源充足、需要改变模型核心能力时考虑全参微调；资源有限、需要快速迭代或多个业务共用一个基座时优先 LoRA。通常先用 LoRA 验证方案，再考虑全参微调。

### Q29. SFT 数据如何构造？

**参考回答：**

数据可以来自人工标注、线上日志筛选和模型生成后人工校验。重点不是数量，而是准确、去重、覆盖业务场景，并保证训练模板和线上推理模板一致；训练集、验证集和测试集要隔离。

### Q30. 什么是灾难性遗忘？如何解决？

**参考回答：**

模型学会新任务后，原有通用能力下降，就叫灾难性遗忘。可以混入通用数据回放、降低学习率和训练轮数、使用 LoRA，并在微调前后跑通用能力回归集。

### Q31. PPO、DPO、GRPO 有什么区别？

**参考回答：**

- `PPO`：需要 Actor、Critic、Reward Model 和 Reference Model，训练复杂、显存大；
- `DPO`：直接用偏好数据优化，不需要在线强化学习，简单稳定；
- `GRPO`：去掉 Critic，用同组样本的相对奖励估计优势，适合有明确可计算奖励的任务。

结合你的项目，可以补充：奖励由任务指标和工具使用效率组成。

### Q32. 如何判断微调有效？

**参考回答：**

至少比较三组结果：原模型、Prompt 方案、微调模型。除了目标任务指标，还要检查通用能力、验证集表现、幻觉率、格式遵循和推理成本，防止只提升训练集或单一指标。

## 五、推理加速

### Q33. FP16、INT8、INT4 怎么选？

**参考回答：**

FP16/BF16 作为效果基线；INT8 通常精度损失较小，适合生产；INT4 最省显存，适合显存受限场景，但需要重点验证长文本、代码和领域任务的精度。量化不能只看显存，还要看延迟和效果。

### Q34. GPTQ、AWQ、FP8 有什么区别？

**参考回答：**

`GPTQ` 和 `AWQ` 都是训练后量化，GPTQ 偏权重重构，AWQ 会重点保护重要激活通道。`FP8` 更依赖新一代 NVIDIA GPU，通常能兼顾性能和精度。具体选型取决于硬件、框架和模型支持情况。

### Q35. FlashAttention 做了什么优化？

**参考回答：**

标准 Attention 会生成很大的注意力矩阵，带来显存和 HBM 读写压力。FlashAttention 使用分块计算和 Online Softmax，不完整保存注意力矩阵，减少显存访问，主要优化训练和 Prefill。

### Q36. 蒸馏和剪枝是什么？

**参考回答：**

蒸馏是用大模型指导小模型学习；剪枝是删除不重要的参数、通道或注意力头。它们都能降低模型规模，但通常需要再微调恢复精度；结构化剪枝更容易获得真实硬件加速。

### Q37. 投机解码是什么？

**参考回答：**

先让小模型快速生成一段 Token，再让大模型一次性验证。验证通过就一次接受多个 Token，从而减少大模型串行 Decode 步数。它适合大小模型输出分布接近、且对延迟敏感的场景。

### Q38. 还有哪些常见推理优化？

**参考回答：**

常见方法包括算子融合、CUDA Graph、KV Cache 分页、Prefix Cache、GQA/MQA、Chunked Prefill、Tensor Parallel、模型量化和编译优化。具体方法要结合瓶颈选择，不能堆技术名词。

## 六、部署与性能排查

### Q39. ONNX、TensorRT、vLLM 的部署链路有什么区别？

**参考回答：**

通用视觉模型通常是：`PyTorch → ONNX → ONNX Runtime/TensorRT → API 服务`。LLM 通常是：`Hugging Face 权重 → vLLM/SGLang → OpenAI 兼容接口`。多模型统一管理时可以使用 Triton。

### Q40. GPU 利用率低怎么排查？

**参考回答：**

我会先判断是四类问题：计算量不足、显存带宽瓶颈、CPU/数据加载慢、GPU 间通信等待。然后用 `nvidia-smi` 看资源，用 `torch.profiler/nsys` 定位具体算子、数据传输或通信瓶颈，再针对性优化。

### Q41. 如何优化推理成本？

**参考回答：**

模型侧使用量化、蒸馏和小模型；框架侧使用连续批处理、Prefix Cache 和 KV Cache 优化；部署侧做弹性扩缩容和 GPU 复用；业务侧限制上下文和最大输出，并缓存高频结果。

### Q42. 训练显存和推理显存有什么区别？

**参考回答：**

训练显存包含权重、梯度、优化器状态、激活和通信缓冲，通常远大于推理。推理主要是权重加 KV Cache，所以训练常用 ZeRO/FSDP/重计算，推理常用量化、PagedAttention 和 Prefix Cache。

## 附一：高频问题一句话回答

| 问题 | 直接回答 |
|---|---|
| 为什么用 DDP？ | 多进程一卡一进程，梯度 AllReduce，性能比 DataParallel 好。 |
| ZeRO-3 解决什么？ | 把参数、梯度和优化器状态切分到多卡，降低单卡显存。 |
| TP 为什么放机内？ | 每层通信频繁，需要 NVLink 高带宽。 |
| vLLM 为什么快？ | PagedAttention 加连续批处理，提高 KV Cache 利用率和 GPU 利用率。 |
| TTFT 是什么？ | 从请求到生成第一个 Token 的时间。 |
| TPOT 是什么？ | 生成阶段平均每个 Token 的耗时。 |
| LoRA 为什么省显存？ | 只训练低秩适配器，不更新完整模型参数。 |
| 量化的风险？ | 显存和延迟下降，但可能损失精度，必须做回归评测。 |
| GPU 利用率低先看什么？ | 先区分计算、带宽、数据和通信四类瓶颈。 |
| Serving 压测看什么？ | TTFT、TPOT、吞吐、P95 延迟、显存和错误率。 |
