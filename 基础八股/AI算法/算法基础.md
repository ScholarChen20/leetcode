# AI 软件岗面试复习

> 使用方式：先记住每题的第一段“短答”，再根据面试官追问展开。回答算法题时，尽量按照“定义 → 原理 → 优缺点 → 选型/实践”的顺序组织。

## 一、机器学习基础

### 1. 什么是集成学习？Bagging、Boosting、Stacking 有什么区别？

**短答：** 集成学习通过组合多个基学习器的预测结果，降低方差、偏差或泛化风险，从而提升整体效果。核心不是简单地“模型越多越好”，而是让基学习器具有一定差异性，并且组合方式合理。

- **Bagging：** 对训练集进行多次有放回采样，分别训练多个模型，最后分类投票、回归平均。各模型可以并行训练，主要用于降低方差。随机森林在此基础上又引入了随机特征采样。
- **Boosting：** 按顺序训练弱学习器，后一个学习器重点拟合前面模型的残差或负梯度，最后进行加权求和，主要用于降低偏差。GBDT、XGBoost、LightGBM 都属于这一类。
- **Stacking：** 第一层训练多个不同类型的模型，将它们对样本的预测结果作为第二层模型的输入。训练元模型时应使用交叉验证产生的 out-of-fold 预测，避免把训练集标签信息泄漏给元模型。

**如何选：** 数据量中等、表格特征较多时优先考虑 GBDT 系列；噪声较大、希望快速得到稳定基线时可以使用随机森林；模型类型差异明显且追求效果上限时考虑 Stacking，但工程复杂度和过拟合风险更高。

**常见追问：**
- Bagging 主要降低方差，Boosting 主要降低偏差，但实际效果还取决于基学习器和正则化。
- Boosting 的基学习器通常不需要很复杂，树的深度较小反而更容易控制过拟合。

### 2. 什么是过拟合？常见解决方法及优缺点是什么？

**短答：** 过拟合是模型在训练集上表现很好，但在未见过的数据上表现明显变差。典型现象是训练 loss 持续下降，而验证 loss 上升，或训练指标显著高于验证指标。

| 方向 | 方法 | 优点 | 代价或风险 |
|---|---|---|---|
| 数据 | 增加真实样本、数据增强、清洗错误标签 | 从根源提升数据覆盖和质量 | 获取数据成本高；增强必须符合任务不变性 |
| 模型 | 减少层数/参数、Dropout、早停 | 直接限制模型复杂度 | 过度约束会欠拟合；Dropout 可能降低收敛速度 |
| 正则化 | L1、L2、Weight Decay | 实现简单，能抑制大权重 | 超参数敏感；L1 可能损失有效特征 |
| 特征 | 特征选择、降维、去除噪声特征 | 减少输入噪声和计算量 | 可能误删弱但有效的特征 |
| 训练 | 交叉验证、学习率调度、合理划分验证集 | 提高模型选择的可靠性 | 训练成本增加；划分不当仍会数据泄漏 |
| 集成 | Bagging、模型平均、Snapshot Ensemble | 通常能提升泛化稳定性 | 推理和维护成本增加 |

**实践排查顺序：** 先检查数据划分和标签质量，再看训练/验证曲线，随后调整模型容量、正则化和数据增强。不要只看到验证集差就盲目加 Dropout，也可能是训练集和线上数据分布不一致。

### 3. GBDT、XGBoost、Random Forest、LightGBM 分别是什么？有什么区别？

| 模型 | 核心思想 | 训练方式 | 主要特点 |
|---|---|---|---|
| Random Forest | 多棵决策树 Bagging | 并行 | 抗噪、稳定、调参相对简单，但模型较大，通常不能像 Boosting 一样充分降低偏差 |
| GBDT | 逐棵拟合损失函数的负梯度 | 串行 | 效果强、解释性较好，但训练不能完全并行，训练时间较长 |
| XGBoost | 工程化的 GBDT | 串行建树，特征/候选切分可并行 | 使用一阶和二阶梯度、显式正则化、缺失值处理和剪枝，精度与稳定性较好 |
| LightGBM | 高效 GBDT | Histogram + Leaf-wise | 直方图分桶减少计算；Leaf-wise 往往收敛快，但小数据或不限制叶子数时更容易过拟合 |

**关键差异：**
1. RF 的树彼此独立，GBDT 系列的树之间存在依赖。
2. XGBoost 常用 level-wise 生长，LightGBM 常用 leaf-wise 生长；后者效果和速度有优势，但需要重点控制 `num_leaves`、`max_depth` 和 `min_data_in_leaf`。
3. XGBoost 的二阶近似和正则项使目标函数优化更充分；LightGBM 通过直方图、GOSS、EFB 等方式降低训练开销。
4. Boosting 对异常点、噪声和参数更敏感；RF 通常更稳，但在复杂非线性关系上效果上限可能较低。

### 4. 常见聚类算法有哪些？如何评价聚类效果？

- **K-Means：** 设定簇数 K，交替执行“样本分配到最近中心”和“按簇内样本均值更新中心”，优化簇内平方误差。速度快，但需要预先指定 K，对初始中心和异常点敏感，适合近似球状、尺度相近的簇。
- **DBSCAN：** 根据 `eps` 邻域和 `min_samples` 判断核心点，通过密度连通形成簇，并能识别噪声点。不需要指定簇数，适合任意形状的簇，但在不同密度或高维数据上参数较难选。
- **层次聚类：** 从每个样本开始逐步合并，形成树状图，再按层级切分。可解释性强，但计算和存储成本较高。
- **GMM：** 假设数据由多个高斯分布混合产生，使用 EM 算法估计参数，输出样本属于每个簇的概率，比 K-Means 更适合椭圆形簇。

**评价指标：**
- 无标签时：轮廓系数越大越好；Calinski-Harabasz 指标通常越大越好；Davies-Bouldin 指标越小越好。还可以结合 SSE 肘部法选择 K。
- 有真实标签时：ARI、NMI、Purity 等可衡量聚类结果与真实类别的一致性。
- 业务上还要看簇的稳定性、可解释性、规模是否合理，以及聚类结果是否能支持后续策略。不能只追求某一个内部指标。

### 5. 数据归一化和标准化怎么选？

**短答：** 先判断模型是否对尺度敏感，再结合分布、异常值和业务约束选择方法。树模型通常不需要缩放；距离、梯度或内积敏感的模型通常需要。

| 方法 | 公式/特点 | 适用场景 | 注意事项 |
|---|---|---|---|
| Min-Max | \(x'=(x-min)/(max-min)\) | 需要固定到 `[0,1]` 等区间，或输入有明确边界 | 对异常值敏感，新数据超出训练范围时可能越界 |
| Z-score | \(x'=(x-\mu)/\sigma\) | 特征近似连续、分布没有极端异常值 | 不保证有界；均值和方差必须只用训练集计算 |
| Robust Scaling | 用中位数和 IQR 缩放 | 异常值较多 | 不能消除所有重尾问题 |
| Log / Box-Cox | 压缩右偏分布，Box-Cox 要求正数 | 收入、计数等强偏态特征 | Box-Cox 不能直接处理非正数，可考虑 Yeo-Johnson |
| Quantile / Rank | 映射为分位数或近似正态分布 | 需要保序且希望减弱异常值影响 | 可能改变原始距离和数值意义 |

**工程要点：** 预处理器只在训练集上 `fit`，再对验证集、测试集和线上数据 `transform`，否则会产生数据泄漏。归一化不是越多越好，要保证训练和推理使用完全相同的处理流程。

## 二、深度学习基础

### 6. Transformer / Decoder-only 的整体结构是什么？各组件做什么？

**整体流程：**

```text
Token Embedding
    → 位置编码/位置信息
    → 多层 Transformer Block
    → Linear LM Head
    → 预测下一个 token
```

一个 Decoder-only Block 通常包含：

1. **Masked Multi-Head Self-Attention：** 每个位置只能关注当前及之前的位置，保证自回归生成时不偷看未来 token。Q、K、V 一般由同一序列线性投影得到。
2. **残差连接：** 将子层输入直接加回输出，改善深层网络中的梯度传播。
3. **LayerNorm 或 RMSNorm：** 稳定激活值分布。现代大模型常使用 Pre-Norm，即先归一化再进入 Attention/FFN。
4. **FFN：** 对每个位置独立进行两次线性变换和非线性激活，负责通道维度上的特征变换。常见形式是 GELU 或 SwiGLU。
5. **LM Head：** 将隐藏状态映射到词表大小，配合交叉熵训练下一个 token。

注意力公式为：

\[
Attention(Q,K,V)=softmax\left(\frac{QK^T}{\sqrt{d_k}}+M\right)V
\]

其中 \(M\) 是因果 mask。除以 \(\sqrt{d_k}\) 是为了控制点积方差，避免 softmax 过度饱和导致梯度变小。标准全注意力的序列长度计算和显存开销近似为 \(O(n^2)\)，长上下文时会成为瓶颈。

**常见变体：**
- **MHA / MQA / GQA：** MQA 让多个 Query 头共享一组 KV；GQA 让一组 Query 头共享一组 KV，可减少 KV Cache 和推理带宽压力。
- **RoPE、ALiBi：** 不同的位置编码方案；RoPE 通过旋转 Q/K 注入相对位置信息。
- **RMSNorm：** 省略均值中心化，计算更简单。
- **SwiGLU：** 门控 FFN，通常用更多参数换取更好的表达能力。
- **FlashAttention：** 主要是 IO-aware 的精确注意力实现，通过分块和片上内存减少 HBM 读写，并不是一种新的注意力数学公式。

### 7. Transformer 如何用于图像任务？相比 CNN 有什么优劣？

以 ViT 为例：

1. 将图像划分为固定大小的 patch，例如 `16×16`。
2. 将每个 patch 展平并通过线性层投影为 token embedding。
3. 加入位置编码，通常还会拼接 `[CLS]` token。
4. 将 token 序列输入 Transformer Encoder，使用 `[CLS]` 或所有 token 的聚合结果完成分类、检测或分割。

**CNN 的优势：** 具有局部连接、权重共享和平移等变性等归纳偏置，数据量较小时更容易训练，计算和显存开销通常更可控。

**Vision Transformer 的优势：** 自注意力可以建立远距离依赖，模型规模增大、预训练数据充足时扩展性好，适合全局关系明显的任务。

**选型：** 数据较少、强调实时性或边缘部署时优先 CNN/轻量混合结构；有大规模预训练模型、需要全局建模或多模态统一表示时考虑 ViT/Swin Transformer。实际项目常使用 CNN 提取局部特征，再用 Transformer 建模全局关系，以平衡效果和成本。

### 8. 卷积层、池化层、全连接层分别做什么？如何选型？

- **卷积层：** 通过局部感受野和权重共享提取空间局部特征，并可通过步幅改变分辨率、通过输出通道改变特征维度。
- **池化层：** 对局部区域做最大值或平均值聚合，降低分辨率和计算量，并带来一定平移鲁棒性，但会丢失精细位置信息。
- **全连接层：** 每个输出神经元连接所有输入，适合做特征融合和最终预测，但参数量容易随空间尺寸膨胀。

**常见实践：** 主干使用卷积块提取特征；需要学习下采样时使用 stride convolution，需要更强平移鲁棒性或压缩计算时使用 pooling；分类任务末端优先使用 Global Average Pooling + Linear，避免直接 Flatten 导致参数量过大。检测、分割等密集预测任务要保留空间信息，不能过早下采样。

### 9. 为什么深度学习训练更倾向用 GPU 而不是 CPU？

深度学习训练的主要计算是矩阵乘法、卷积和逐元素运算，具有很高的数据并行性。GPU 通过大量计算核心和 Tensor Core 提供更高的并行吞吐，并且显存带宽通常远高于 CPU 内存，适合连续处理大批量张量。

CPU 核心更少但单核能力和控制逻辑更强，适合数据预处理、分支多的程序、系统调度和小规模任务。GPU 也不是任何情况下都更快：模型很小、batch 很小、数据加载慢、频繁在 CPU/GPU 间拷贝，或者算子不支持 GPU 时，GPU 利用率会很低。

**工程优化方向：** 使用 pinned memory 和异步拷贝，合理设置 `num_workers`，增大有效 batch，使用 AMP/混合精度，减少不必要的数据搬运，并通过 profiler 区分计算瓶颈和 IO 瓶颈。判断硬件效率时不能只看 FLOPS，还要看内存访问和算子利用率。

### 10. 标准卷积、空洞卷积、深度可分离卷积、转置卷积有什么区别？

| 类型 | 核心操作 | 典型用途 | 主要问题 |
|---|---|---|---|
| 标准卷积 | 卷积核同时在空间和输入通道上做计算，并生成输出通道 | 通用特征提取 | 参数量和计算量较大 |
| 空洞卷积 | 在卷积核采样点之间加入间隔，扩大感受野 | 语义分割、多尺度上下文 | 空洞率过大可能出现 gridding artifacts，局部信息不连续 |
| 深度可分离卷积 | Depthwise 对每个通道独立卷积，再用 Pointwise `1×1` 融合通道 | MobileNet、端侧模型 | 通道交互能力依赖 `1×1` 卷积，硬件未必总能获得理论加速 |
| 转置卷积 | 学习型上采样，通过参数化的反向尺寸映射扩大特征图 | 分割解码器、生成模型 | stride/kernel 配置不当可能产生棋盘格伪影 |

标准卷积参数量约为 \(K_hK_wC_{in}C_{out}\)；深度可分离卷积约为 \(K_hK_wC_{in}+C_{in}C_{out}\)，因此在大卷积核或通道数较大时节省明显。

**取舍：** 追求精度和通用性时使用标准卷积；需要扩大感受野且不能明显降低分辨率时使用空洞卷积；端侧部署优先考虑深度可分离卷积；上采样时根据伪影和硬件支持情况，在转置卷积、插值 + 卷积、PixelShuffle 之间选择。

### 11. 训练过程中 loss 突然上升，如何定位？

我会先保留现场，再按“现象确认 → 数据 → loss → 优化 → 数值和实现”的顺序排查：

1. **确认是否真实异常：** 记录异常 step、batch、输入样本和随机种子；与最近一次稳定 checkpoint 对比，确认是单个 batch 异常还是从此持续发散。
2. **检查数据：** 输入、标签、增强结果是否有 NaN/Inf、越界值、空样本、错误标签或异常长度；检查数据集是否在训练过程中被错误修改。
3. **检查 loss 实现：** 分类时确认 `CrossEntropyLoss` 接收 logits 而不是 softmax 后的概率；二分类确认 `BCEWithLogitsLoss` 不要重复 sigmoid；检查 label 范围、padding mask、样本权重和 reduction 是否正确。
4. **检查学习率和优化器：** 是否刚发生 warmup 结束、scheduler 重复 step、梯度累积步数变化、断点恢复时学习率错误；必要时降低学习率并开启梯度裁剪。
5. **检查梯度和参数：** 记录梯度范数、参数范数、更新量、激活最大值以及 AMP 的 loss scale，判断是梯度爆炸、梯度消失还是某层数值溢出。
6. **检查模型和分布式逻辑：** 确认参数确实加入 optimizer、`train/eval` 模式正确、BN 统计没有异常、混合精度和多卡同步逻辑正确。
7. **最小化复现：** 用一个 batch 反复训练，确认模型能否过拟合；再逐步加入数据增强、混合精度、分布式和新模块，用二分法定位变更来源。

不要一开始就盲目调小学习率。若只有少数样本触发，应优先定位样本和数据处理；若所有 batch 同时发散，再重点检查学习率、梯度和数值稳定性。

## 三、训练、评估与工程实践

### 12. 训练集、验证集、测试集如何划分？什么是数据泄漏？

- **训练集：** 用于更新模型参数。
- **验证集：** 用于选择模型结构、超参数、阈值和 checkpoint，不能参与参数拟合。
- **测试集：** 只在最终方案确定后使用，用于估计泛化能力。

数据泄漏是指训练过程间接使用了本不应该看到的信息，例如用全量数据计算归一化均值、将同一用户的样本随机拆到训练和验证集、特征中包含未来时刻信息、先用测试集调参等。

**正确做法：** 按用户、设备、时间或业务实体进行合理切分；所有预处理、特征选择和统计量都只在训练集上拟合；时间序列任务必须遵守时间顺序。线上指标异常好但上线后迅速下降时，优先排查泄漏和分布偏移。

### 13. Accuracy、Precision、Recall、F1、AUC 分别是什么？类别不平衡时怎么选？

- **Accuracy：** \((TP+TN)/(TP+TN+FP+FN)\)，类别均衡时直观，类别不平衡时可能失真。
- **Precision：** \(TP/(TP+FP)\)，预测为正的样本中有多少是真的，适合误报成本高的场景。
- **Recall：** \(TP/(TP+FN)\)，真实正样本中找回多少，适合漏报成本高的场景。
- **F1：** Precision 和 Recall 的调和平均，用于综合权衡二者。
- **ROC-AUC：** 衡量不同阈值下 TPR 与 FPR 的排序能力；类别极不平衡时还应关注 PR-AUC。

**实践中：** 先明确 FP 和 FN 哪个成本更高，再通过阈值、类别权重、过采样/欠采样调整策略。训练阶段可以使用 weighted cross entropy 或 focal loss；评估时不要只报一个 Accuracy，应同时给出混淆矩阵、正负类指标，并在真实业务分布上验证。

### 14. BatchNorm 和 LayerNorm 有什么区别？为什么 Transformer 常用 LayerNorm？

| 对比项 | BatchNorm | LayerNorm |
|---|---|---|
| 统计维度 | 通常对 batch 和空间维度统计，每个通道独立 | 通常对单个样本的特征维度统计 |
| 是否依赖 batch | 依赖，batch 太小时统计不稳定 | 不依赖 batch，单样本即可计算 |
| 训练/推理 | 训练用当前统计量，推理常用 running statistics | 通常训练和推理计算方式一致 |
| 常见场景 | CNN | Transformer、RNN、变长序列 |

Transformer 常用 LN，原因是序列长度可变、batch 可能较小，且不同样本的 token 分布差异较大；BN 的跨样本统计可能引入噪声。小 batch 的 CNN 也可以考虑 GroupNorm 或 SyncBN。

### 15. Adam、AdamW 和 SGD 有什么区别？学习率如何设置？

- **SGD + Momentum：** 使用梯度和历史动量更新参数，计算简单、泛化通常较好，但对学习率和调度策略较敏感。
- **Adam：** 为每个参数维护一阶矩和二阶矩，具有自适应学习率，通常启动快、对稀疏梯度更友好。
- **AdamW：** 将 Weight Decay 与梯度更新解耦，比直接在 Adam 梯度中加入 L2 项更符合权重衰减的预期，是 Transformer 中的常用选择。

学习率过大可能 loss 发散，过小则收敛慢或停在较差位置。常见策略有 Warmup、Step Decay、Cosine Annealing、Linear Decay 和 ReduceLROnPlateau。大模型训练常使用 Warmup + Cosine/Linear Decay；改变 batch size 时通常需要重新调学习率，并关注有效 batch size（实际 batch × 梯度累积 × 卡数）。

### 16. 梯度消失和梯度爆炸的原因及解决方法是什么？

深层网络反向传播是多层导数相乘：导数长期小于 1 可能导致梯度消失，长期大于 1 可能导致梯度爆炸。深层网络、RNN、饱和激活函数、初始化不当和学习率过大都可能加剧问题。

**解决方法：**
- 使用 ReLU、GELU、LeakyReLU 等非饱和激活；
- 使用 Xavier/He 初始化；
- 引入残差连接、Pre-Norm、合理的归一化；
- 梯度爆炸时使用 Gradient Clipping；
- 选择合适的学习率和 Warmup；
- 对 RNN 使用 LSTM/GRU 或截断反向传播；
- 混合精度训练中使用 loss scaling，并监控溢出情况。

定位时不要只看 loss，要同时监控每层梯度范数、参数范数和激活分布。

### 17. 类别不平衡如何处理？

**数据层面：** 过采样少数类、欠采样多数类、使用符合业务的增强方式。过采样可能过拟合，欠采样可能丢失多数类信息。

**损失层面：** 使用类别权重、Focal Loss 或调整正负样本采样比例。权重过大可能造成训练不稳定，需要在验证集上调节。

**预测层面：** 不固定使用 0.5 作为阈值，根据 Precision-Recall 曲线和业务成本选择阈值。

**评估层面：** 重点关注 Recall、Precision、F1、PR-AUC、混淆矩阵，必要时按用户/时间分层评估。采样只应发生在训练集，验证和测试集应尽量保持真实分布。

### 18. 模型上线前如何做推理优化？

我会从效果、延迟、吞吐、显存和稳定性共同评估，而不是只追求单点精度：

1. **模型侧：** 剪枝、蒸馏、减少层数或通道数。
2. **数值侧：** FP16/BF16 混合精度，或 INT8/INT4 量化；量化后重点验证精度和异常样本。
3. **算子侧：** 使用 ONNX、TensorRT 等推理后端，融合 Conv + BN + Activation，减少 kernel launch 和内存拷贝。
4. **服务侧：** 动态 batching、请求并发控制、线程池、缓存和超时降级。
5. **数据侧：** 预处理与后处理并行化，避免 CPU/GPU 往返传输。
6. **监控侧：** 监控 P50/P95/P99 延迟、吞吐、显存、错误率、输入分布和线上效果漂移。

优化前先建立基准：固定输入和 batch，分别测预处理、模型前向、后处理和端到端耗时，确认瓶颈后再优化。

## 四、项目深挖回答模板

### 19. 面试官让你介绍一个项目，怎么回答？

建议按照以下顺序，控制在 1～2 分钟，再根据追问展开：

1. **背景和目标：** 业务问题是什么，输入输出是什么，核心指标是什么。
2. **数据和难点：** 数据规模、标签来源、类别分布、噪声、长尾或线上约束。
3. **方案：** 为什么选择当前模型，关键模块和训练策略是什么。
4. **实验：** 基线是什么，做过哪些 ablation，指标如何变化。
5. **工程：** 训练资源、推理耗时、模型大小、部署方式和监控方案。
6. **结果和复盘：** 最终线上收益、失败方案、当前不足和下一步计划。

**回答原则：** 所有指标都要能说明数据集、评估方式和对比基线；不要只说“用了某个模型效果很好”，要讲清楚自己负责的部分、做过的取舍，以及如何验证结论。

### 20. 如何回答“你遇到过最难的问题是什么”？

可以使用“问题—定位—方案—验证—复盘”的结构：

- **问题：** 明确现象和影响，例如线上延迟升高或验证集指标异常。
- **定位：** 说明如何通过日志、可视化、对照实验和二分法缩小范围。
- **方案：** 讲清候选方案、选择依据以及精度和成本之间的取舍。
- **验证：** 给出离线、灰度和线上指标，说明是否排除副作用。
- **复盘：** 总结形成的监控、测试或流程改进，体现可迁移的工程能力。
