## CPR 奖励函数设计思路

### 核心一句话

> 传统奖励问"结果有多接近 GT？"，CPR 改问"**Agent 的推理过程有多像专家医生？**"

### 根本问题

现有方法（IoU/Dice/Acc）都是**结果导向的标量奖励**，有三个致命缺陷：

1. **信用分配难** — 多轮交互不知道哪一步贡献大
2. **过程无语义** — 只看像素匹配，不看临床合理性（可能学出"IoU 高但临床不合理"）
3. **任务间无迁移** — 分类/检测/分割各自独立，复合任务协同性无法体现

### 三个创新模块

## 三、CPR 的三个创新模块

### 模块 A：Step-Level Clinical Reasoning Score (步骤级临床推理分)

#### 核心思想

每一轮 Agent 的操作，从四个临床维度评估其"合理性"：

```
对 Agent 每一轮操作 (obs_t, action_t) 计算:

1. 定位准确性 (Localization)
   "这一步操作是否准确指向了目标区域？"
   - add_bbox: 框是否覆盖 GT 区域？→ bbox覆盖率
   - add_point: 点是否落在错误区域内？→ 是否在FN/FP区域
   - detect: 检测框是否包含目标？→ IoU
   - classify: 分类区域是否包含完整病灶？→ 区域覆盖率

2. 信息增益 (Information Gain)
   "这一步操作是否提供了新的诊断信息？"
   - 分割: IoU 是否提升？→ delta_IoU
   - 检测: 是否发现了之前未检测到的区域？→ new_coverage
   - 分类: 是否改变了诊断结论？→ entropy_change
   - 如果操作未带来任何信息变化 → 信息增益=0 (浪费的步骤)

3. 临床一致性 (Clinical Consistency)
   "这一步操作是否符合临床推理逻辑？"
   - 分割细化应该在检测之后（先定位再细化）
   - 分类应该在分割之后（先看清楚再判断性质）
   - 不应该先分类再分割（顺序不合理）
   - 评估: action_sequence 是否符合 task → segment → classify 的临床流程

4. 决策置信度 (Decision Confidence)
   "Agent 在这一步的决策是否'有依据'？"
   - 如果 Agent 输出了推理文本 (chain-of-thought)
   - 评估推理是否与当前观察一致
   - 如果没有推理，用 VLM 的 logit entropy 作为不确定性度量
```

#### 数学形式

```
step_score_t = α₁ × localization_t + α₂ × info_gain_t + α₃ × consistency_t + α₄ × confidence_t

CPR_reward = Σ_t  γ^t × step_score_t
```

其中 γ 是折扣因子，越早的步骤权重越高（鼓励早决策）。

### 模块 B：Cross-Task Synergy Score (跨任务协同分)

#### 核心思想

复合任务中，不同工具的输出应该**互相增强**，而不仅仅是串行执行。

#### 具体设计

```
# 检测 → 分割 的协同
synergy_det_seg = 
  如果 detect 的框被 add_bbox 直接复用 → +bonus (信息传递)
  如果 add_bbox 完全忽略了 detect 的结果 → -penalty (信息浪费)

# 分割 → 分类 的协同
synergy_seg_cls =
  如果 classify 的 region 和 segment 的 mask 区域对齐 → +bonus
  如果 classify 用了完全不同的区域 → -penalty (分割白做了)

# 检测 → 分类 的协同 (跳过分割)
synergy_det_cls =
  如果在未分割的情况下直接从检测框做分类 → -penalty (跳过了关键步骤)
  除非检测置信度极高 (>0.95) → 豁免

# 三任务协同
synergy_full =
  detect → segment → classify 的完整链路且信息逐级传递 → +large_bonus
```

#### 创新点

传统奖励只看"每个子任务的结果对不对"，**不看子任务之间是否协同**。CPR 首次引入跨任务的信息流评估，让 Agent 学会"前一步的结果要为后一步服务"。

---

### 模块 C：Adversarial Clinical Consistency (对抗性临床一致性)

#### 核心思想

用一个小型"临床判官"模型（Clinical Judge）来评估 Agent 的决策过程是否"医学上合理"，而不是只看几何指标。

#### 架构

```
Agent 轨迹: detect → add_bbox → add_point → classify → stop
     │
     ▼
┌─────────────────────────────────┐
│  Clinical Judge (轻量VLM/规则)   │
│                                 │
│  输入: 完整轨迹 + GT             │
│  输出:                           │
│    1. 推理合理性评分 (0-1)        │
│    2. 是否有临床危险操作 (bool)   │
│    3. 漏诊/误诊风险 (0-1)        │
└─────────────────────────────────┘
     │
     ▼
CPR_reward += judge_score × safety_weight
```

#### Clinical Judge 的三种实现路线

| 路线 | 方法 | 优劣 |
|------|------|------|
| 规则版 | 医学指南编码为规则 | 简单但覆盖面窄 |
| 模型版 | 用 GPT-4o / Med-PaLM 评估 | 强但推理成本高 |
| 学习版 | 训练一个小型临床判别器 | 折中，需要标注数据 |

#### 创新点

传统奖励函数是"无脑的几何比较器"。CPR 引入"有医学知识的判官"，让奖励信号包含**临床语义**。这是第一次把 process reward 的思想从数学推理迁移到医学视觉 Agent。

---

## 四、CPR 完整公式

```
CPR_reward = 
    λ₁ × Σ_t γ^t × step_score_t           # 模块A: 步骤级临床推理
  + λ₂ × synergy_score                     # 模块B: 跨任务协同
  + λ₃ × clinical_judge_score              # 模块C: 临床一致性
  + λ₄ × final_result_score                # 传统结果分 (IoU/Dice/Acc)
  - λ₅ × safety_penalty                    # 安全惩罚 (漏诊/误诊)
```

其中:
- `step_score_t` 包含定位/信息增益/一致性/置信度四维
- `synergy_score` 包含检测→分割→分类的信息流评估
- `clinical_judge_score` 是临床判官的综合评分
- `final_result_score` 是传统几何指标 (作为保底)
- `safety_penalty` 对漏诊/误诊做重罚

---


### 关键工程判断

文档特别强调了**渐进式实现**（Phase 1 规则版 CPR 零额外模型 → Phase 2 加临床判官 → Phase 3 安全约束），并且计算开销可控（规则版仅 +7%）。这是把数学推理领域的 PRM 思想**首次迁移到医学视觉 Agent** 的卖点。

---

一句话总结：**它不是"更好的 IoU"，而是改变奖励范式——从"结果对错"到"过程像不像专家"。**
