# CPR 奖励设计：从早期概念到当前 CPR v2

> 本文将早期 CPR 概念与当前代码实现分开描述。当前仓库实现的是低开销、规则驱动的 CPR v2；Clinical Judge、推理置信度和医生一致性评价仍属于后续方向。

## 1. 为什么需要过程奖励

传统 IoU、Dice、检测 Recall 或分类 Accuracy 主要评价最终结果。在多轮工具调用中，仅看最终结果会遇到三个问题：

1. 无法判断哪一次工具调用真正改善了当前状态；
2. 无法衡量检测框是否被分割工具复用、分割区域是否被 ROI 分类使用；
3. 无法区分必要交互、重复调用、失败调用和高质量后的无效细化。

CPR 的目标不是替代终局质量，而是在终局质量之上，为 Agent 提供事件级、可解释的训练信号。

## 2. 当前 Agent 轨迹表示

一次 rollout 被记录为工具事件序列。事件包含工具名称、参数、成功状态、工具结果和局部状态；分割事件还记录 `mask_before` 与 `mask_after`。当前主要工具包括：

```text
classify / detect / add_bbox / add_point / finish_instance / stop_action
```

对于多实例任务，事件还可包含 `instance_id`。`finish_instance` 表示完成一个候选病灶，`stop_action` 表示结束整张图像的 episode。

## 3. CPR v2 当前组成

### 3.1 终局质量 `Q_terminal`

纯分类、检测和分割任务分别使用对应任务质量。复合任务当前实现为：

```text
Q_terminal = 0.25 × Q_detection
           + 0.45 × Q_segmentation
           + 0.30 × Q_ROI_classification
```

分割权重最高，因为当前项目的主目标仍是病灶边界精细分割；分类和检测主要承担语义与空间先验作用。

多实例任务会先进行实例匹配，再汇总实例级分割质量，并根据漏检实例和误检实例增加安全惩罚。

### 3.2 事件级过程增益 `Q_process`

对于分割动作，使用调用前后的状态变化计算增益：

```text
gain_t = quality(mask_after_t) - quality(mask_before_t)
```

其中 `quality` 综合 IoU 和 Dice。检测、分类和停止动作则依据对应结果质量、当前任务和终止时机映射到过程分。工具失败、无效细化或重复调用不会因为最终结果尚可而自动获得正奖励。

### 3.3 跨工具信息流协同 `Q_synergy`

CPR v2 不只检查工具是否出现，还检查上游输出是否真正进入下游动作：

```text
筛查分类 → 检测：分类事件发生在检测之前，且筛查结果有效
检测 → 分割：detect 框与 add_bbox 框的 IoU
分割 → ROI 分类：分类 region 对最终 mask 的覆盖率
```

因此，`detect → add_bbox` 不是简单的顺序奖励，而是对检测框和分割框的几何复用进行度量；ROI 分类也必须使用与最终分割结果对齐的区域。

### 3.4 任务条件化策略分 `Q_policy`

不同任务不应使用同一套固定动作要求。例如：

- 分类任务需要出现 `classify`，不应因为没有检测或分割而被惩罚；
- 检测任务需要出现 `detect`；
- 分割任务需要先初始化分割，再允许点提示细化；
- 复合任务根据任务定义检查筛查、检测、分割和 ROI 表征是否合理；
- 正常样本在满足条件时可以 `classify → stop_action`，但病灶样本漏诊会触发安全惩罚。

### 3.5 格式分 `Q_format`

格式分检查工具调用是否符合 schema、参数是否可解析、是否以合法停止动作结束，以及是否违反基本工具顺序约束。它是训练稳定性辅助项，不代表临床质量。

### 3.6 动作成本 `C_action`

动作成本区分重复参数调用、工具失败、与当前任务无关的调用、已达到较高质量后的无效细化，以及不必要的额外停止或错误终止。这不是简单地惩罚所有工具调用，而是让 Agent 在质量、效率和安全之间进行权衡。

### 3.7 规则式安全惩罚 `P_safety`

当前安全项基于 GT 标签、GT mask、GT bbox、检测结果和分割质量编码风险，重点惩罚病灶样本被判断为正常、病灶没有被检测到、病灶分割质量过低、正常样本出现明显误检，以及多实例任务漏掉候选实例或产生额外实例。

这是训练阶段的规则式风险信号，不等同于临床安全证明，也不替代医生评价。

## 4. 当前代码对应的复合任务公式

当前 `cpr_reward.py` 的复合任务可以概括为：

```text
R = clip(
      0.60 × Q_terminal
    + 0.20 × Q_process
    + 0.10 × Q_synergy
    + 0.05 × Q_policy
    + 0.05 × Q_format
    - C_action
    - P_safety,
    -1, 1
)
```

单任务使用任务对应的终局质量，不强行要求完整复合流程：

```text
R_single = clip(
      0.70 × Q_terminal
    + 0.20 × Q_process
    + 0.05 × Q_policy
    + 0.05 × Q_format
    - C_action
    - P_safety,
    -1, 1
)
```

## 5. 早期概念与当前实现的边界

早期 CPR 设计曾考虑 Clinical Judge、对推理文本进行医学合理性评价、使用 logit entropy 或显式置信度、显式的 `γ^t` 步骤级时间折扣，以及医生对轨迹合理性和安全性的人工评价。

这些内容可以作为后续研究路线，但目前不能写成 CPR v2 已实现模块。当前代码的过程奖励来自结构化工具事件、GT 和视觉状态变化，不依赖独立 Clinical Judge，也不应声称已经完成医生一致性验证。

## 6. 当前验证状态

当前可以确定地说：CPR v2 代码已实现；奖励信息可以通过 Agent loop 透传；事件轨迹、终局质量、过程增益、协同、策略/格式、动作成本和安全惩罚已有局部测试；多实例相关奖励已加入实例匹配和实例级风险项。

当前不能直接声称：完整 Ray、模型权重和三类工具服务下的 GRPO 已稳定收敛；CPR v2 相对终局奖励已经稳定提升最终分割性能；已完成所有消融、跨数据集泛化和统计显著性分析；Clinical Judge 或医生评价已参与当前训练。

## 7. 推荐面试回答

> 当前实现的是规则版 CPR v2。它以终局任务质量为主，同时记录每次工具调用前后的状态变化，计算分割 mask 增益，并检查检测框到分割框、分割结果到 ROI 分类区域的信息复用。此外，奖励还包含任务条件化策略、格式约束、动作成本和规则式安全惩罚。这样做的重点是让 Agent 不仅追求最后的 IoU，也学习哪些工具调用真正有效、什么时候应该继续修正以及什么时候可以安全停止。Clinical Judge、医生一致性评价和完整 GRPO 增益验证仍属于后续工作。
