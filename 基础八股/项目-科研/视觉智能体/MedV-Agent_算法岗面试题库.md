# MedV-Agent：AI 算法岗项目/科研面试题库（当前进度版）

> 更新时间：2026-09-16  
> 项目定位：以交互式病灶分割为核心、由 Qwen3-VL 系列模型调度分类/检测/分割工具的多任务医学视觉 Agent。  
> 使用原则：严格区分“已实现”“局部验证”“实验中”和“规划中”。26%、0.58 pp、60k 等数字只有在原始实验记录归档后才可作为正式结果。

## 1. 30 秒项目介绍

我做的是一个面向医学图像分类、检测和交互式分割的多工具视觉 Agent。系统以 Qwen3-VL 系列模型作为决策层，把 BioMedCLIP、Grounding DINO 和 IMISNet/MedSAM2 封装成可调用工具。模型根据任务指令、当前视觉状态和工具反馈决定是否筛查、检测、初始化分割、继续点提示修正、复用 ROI，以及何时停止。

当前工作重点已经从单目标交互式分割扩展到任务条件化工具调度、跨工具信息流、多实例候选管理和规则版 CPR v2 过程奖励。代码、数据工程和训练骨架已经打通，但完整 GRPO 稳定收敛、消融、跨数据集泛化和最终量化结果仍需以正式实验记录为准。

## 3. 数据集与任务定义

### 3.1 工程支持与当前实验范围

| 范围 | 数据集 | 正确说法 |
|---|---|---|
| 工程支持 | BUSI、Kvasir-SEG、COVID-19、TN3K、AbdomenCT、AbdomenMR | 预处理链路兼容，包含统一字段和 CT/MR 2D 化流程 |
| 当前多病灶实验 | BUSI、Kvasir-SEG、TN3K | 当前 SFT/RL/评估主范围 |
| 后续扩展 | COVID-19、AbdomenCT、AbdomenMR | 暂不写成已完成本轮完整 RL 对比 |

BUSI 可用于正常/病灶筛查和良恶性相关任务；Kvasir-SEG 更适合作为息肉存在性筛查、检测和分割数据；TN3K 重点是甲状腺结节定位与分割。不能把三者都包装成同构的良恶性诊断数据。

### 3.2 2D/3D 口径

CT/MR 工程链路支持 `3D NIfTI → 2D 切片 → mask/bbox → parquet`，目的是复用当前 2D VLM 和工具接口。当前论文和面试口径应称为跨器官、跨模态的 2D 医学图像验证，不应写成原生 3D 临床决策系统。

## 4. 系统架构与动作空间

### Q1：系统整体架构是什么？

上层是 Qwen3-VL 系列策略模型，中间是 Agent loop，底层是三个视觉后端 API。模型生成 tool call，Agent 执行工具，再把文本、检测 overlay 或 mask overlay 回灌给模型。

### Q2：各工具分别做什么？

| 工具 | 后端 | 作用 |
|---|---|---|
| `classify` | BioMedCLIP | 全图筛查或 ROI 分类 |
| `detect` | Grounding DINO | 根据目标描述产生候选框 |
| `add_bbox` | IMISNet/MedSAM2 | 初始化或修正分割 |
| `add_point` | IMISNet/MedSAM2 | 交互式细化 |
| `finish_instance` | Agent 状态管理 | 完成一个候选病灶 |
| `stop_action` | Agent 策略 | 结束整张图像 episode |

### Q3：为什么不是固定流水线？

固定流程可以作为基线，但不能处理正常样本提前停止、用户已指定目标时跳过筛查、检测失败后重试、低质量 mask 继续修正和多候选实例逐个完成等情况。Agent 的价值在于根据中间状态动态决定下一步。

### Q4：多实例如何处理？

检测结果会注册为 `candidate_0`、`candidate_1` 等实例。每个实例独立维护 `instance_id` 和分割 session，执行 `add_bbox → add_point* → finish_instance`。所有实例处理完成后才可以 `stop_action`。`finish_instance` 不是图像级停止动作。

## 5. CPR v2 奖励

### Q5：CPR v2 的核心公式是什么？

当前复合任务实现可概括为：

```text
R = clip(
      0.60 × Q_terminal
    + 0.20 × Q_process
    + 0.10 × Q_synergy
    + 0.05 × Q_policy
    + 0.05 × Q_format
    - C_action
    - P_safety,
    -1, 1
)
```

其中：

```text
Q_terminal = 0.25 × Q_detection
           + 0.45 × Q_segmentation
           + 0.30 × Q_ROI_classification
```

纯分类、检测和分割任务使用任务对应的终局质量，不强行要求所有工具都被调用。

### Q6：事件级过程奖励如何计算？

分割动作记录 `mask_before` 与 `mask_after`，用 IoU/Dice 综合质量变化计算状态增益。检测、分类和停止动作根据当前任务、返回质量和终止时机计算过程分。工具失败、重复参数和无效细化通过动作成本或负向过程反馈约束。

### Q7：跨工具协同如何量化？

不是简单奖励工具按顺序出现，而是检查信息是否真正传递：

```text
筛查分类 → 检测：分类是否先于检测且结果有效
检测 → 分割：IoU(bbox_detect, bbox_add_bbox)
分割 → ROI 分类：region 对最终 mask 的覆盖率
```

### Q8：Clinical Judge 是否已经实现？

没有。当前 CPR v2 是基于结构化工具事件、GT 和视觉状态变化的规则奖励。Clinical Judge、推理文本医学合理性、logit entropy 置信度和医生一致性评价属于后续方向，不能写成当前实现。

## 6. SFT、GRPO 与工程边界

### Q9：SFT 和 RL 分别解决什么？

SFT 学工具 schema、参数格式、多轮反馈和基本调用先验；GRPO 优化工具选择、信息复用、错误恢复、交互成本和停止策略。当前已经有 SFT 数据生成、parquet 数据链路、Agent loop、CPR v2 和训练脚本，但完整端到端稳定收敛仍在验证。

### Q10：为什么用 GRPO 而不是 PPO？

GRPO 使用同一输入的多条 rollout 做组内相对比较，不需要单独训练 critic，适合多轮工具调用和规则可验证奖励。选择 GRPO 是训练方案设计，不等同于已经获得 RL 性能提升。

## 7. 实验结果的严格口径

### Q11：26% 的交互步数下降如何计算？

只有在相同测试集、目标病灶、最大交互轮次、停止条件和评估脚本下，统计每例有效分割交互次数，才可以使用：

```text
reduction = (S_IBIS - S_MedV) / S_IBIS × 100%
```

其中应明确 MedV-Agent 统计哪些分割动作、IBISAgent 统计哪些点击动作。分类和检测调用不能偷偷混入“分割交互步数”。

### Q12：0.58 pp 如何计算？

如果同一测试集上：

```text
ΔIoU = mIoU_MedV - mIoU_IBIS = 0.0058
```

那么百分制是 `0.58` 个百分点，即 `0.58 pp`，不是相对提升 `0.58%`。正式报告还应同时给出样本数、标准差、置信区间和统计检验。

### Q13：目前能不能把 26%、0.58 pp 和 60k 写进简历？

在逐病例统计、原始日志、代码版本、模型 checkpoint 和公平基线配置没有归档前，不建议写成确定性结果。当前统一标记为“待实验记录复核”。

## 9. 一分钟答辩总结

> MedV-Agent 不是把多个视觉模型简单串起来，而是把分类、检测和交互式分割建模为可调度工具，由 Qwen3-VL 系列模型根据任务和视觉反馈决定工具选择、参数生成、中间结果复用、实例完成和停止。当前主要贡献包括多任务工具化、标注复用的数据工程、多实例状态管理和规则版 CPR v2。CPR v2 将终局质量、事件级状态增益、跨工具信息流、任务策略、动作成本和规则式安全风险纳入奖励。代码与局部验证已经完成，但最终研究结论仍取决于完整 GRPO、消融、泛化和可复现统计结果。
