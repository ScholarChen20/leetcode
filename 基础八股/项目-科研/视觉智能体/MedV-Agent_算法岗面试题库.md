# MedV-Agent：AI 算法岗项目/科研面试题库

> 项目定位：以高精度病灶分割为核心，将全图筛查分类作为语义先验、检测作为空间先验、交互式分割作为边界精描，并在分割后进行 ROI 级病灶表征的医学视觉智能体。  
> 当前实验数据：BUSI、Kvasir-SEG、TN3K。  
> 使用原则：准确区分“已完成实验结果”“已实现且已单元验证的方法”“仍需完整 RL 对比验证的结论”。不要将工具集成描述成端到端模型训练，也不要把规划中的实验结果表述为最终结论。

---

## 1. 30 秒项目介绍

我做的是一个面向病灶精细分割的多工具医学视觉 Agent。传统交互式分割通常只让模型反复选点修正 mask，而我的方法将临床阅片中的渐进式过程建模为：先用全图分类进行异常筛查和风险初判，再用检测定位候选病灶，以检测框初始化交互式分割，最后基于分割 ROI 做病灶表征。

系统以 `Qwen3-VL-8B` 为决策中枢，调度 BioMedCLIP、Grounding DINO 和 MedSAM2/IMISNet 等专用视觉工具；训练上采用 SFT 建立工具调用先验、GRPO 优化多轮决策，并设计 CPR v2 奖励联合考虑终局分割质量、每步 mask 增益、跨工具信息复用、无效操作成本和漏诊风险。

在 BUSI、Kvasir-SEG 和 TN3K 的实验设置中，分割交互步数相对 IBISAgent 基线降低 `26%`，IoU 提升 `0.58` 个百分点（pp）。

### 2.1 不能写错的表述

- 不写“单模型完成分类、检测、分割”：准确说法是“单一 VLM Agent 调度多个专用视觉工具”。
- 不写“总体工具调用步数降低 26%”，除非统计中包含了 `classify`、`detect`、`add_bbox`、`add_point` 等全部工具且基线也有严格可比动作空间。
- 推荐写“**分割交互步数降低 26%**”，与 IBISAgent 的点击式交互分割设定对齐。
- 不写“IoU 提升 0.58%”：推荐写“**IoU 提升 0.58 个百分点（0.58 pp）**”。如果原始记录是 `0.0058` 的绝对差，则对应 `0.58 pp`。
- 不写“临床诊断系统”或“替代医生诊断”：准确说法是“临床过程启发的诊断辅助分割 Agent”。

### 3.2 训练、验证、测试划分必须准备的材料

## 4. 两个核心指标的严格计算口径

### 4.1 “分割交互步数降低 26%”如何计算

该结果应定义为：在**同一测试集、同一目标病灶、相同最大交互轮次和相同终止条件**下，MedV-Agent 相对 IBISAgent 完成病灶分割所需的平均交互步骤减少比例。

对于每个阳性病例 `i`，定义：

```text
s_i = 从首次分割提示到 stop 之前的有效分割交互次数
```

本项目推荐将有效分割交互定义为：

```text
s_i = #add_bbox + #add_point
```

若 IBISAgent 只使用正/负点击，则其对应定义为：

```text
s_i(IBISAgent) = #positive_click + #negative_click
```

注意：`classify` 和 `detect` 是本项目为了提供语义/空间先验而新增的辅助工具，**不应混入该“分割交互步数”对比**，否则会与 IBISAgent 的动作空间不公平。它们应单独报告为“端到端总工具调用次数”。

计算每个方法在测试阳性样本集合 `D+` 上的平均交互步数：

```text
S_MedV = (1 / |D+|) × Σ_i s_i(MedV-Agent)
S_IBIS = (1 / |D+|) × Σ_i s_i(IBISAgent)
```

最后计算相对下降比例：

```text
Step reduction = (S_IBIS - S_MedV) / S_IBIS × 100%
               = 26%
```

换句话说，报告“降低 26%”时，必须能拿出如下原始统计：

| 指标 | 需要保留的原始值 |
|---|---|
| 测试病例数 | `N_positive = ____` |
| IBISAgent 平均分割交互步数 | `S_IBIS = ____` |
| MedV-Agent 平均分割交互步数 | `S_MedV = ____` |
| 相对下降 | `(S_IBIS - S_MedV) / S_IBIS = 26%` |
| 方差 | 标准差、标准误或 95% CI |

#### 面试标准回答

> 26% 指的是分割交互效率，不是把所有工具调用都算在一起。对于每个阳性病例，我统计从开始分割到停止所需的 `add_bbox` 和 `add_point` 次数；IBISAgent 对应统计其正负点击次数。对测试集求平均后，用 `(IBISAgent 平均步数 - MedV-Agent 平均步数) / IBISAgent 平均步数` 计算，得到 26%。分类和检测调用会单独作为端到端总成本报告，因为它们不属于与 IBISAgent 可直接比较的分割交互动作。

### 4.2 “IoU 提升 0.58 pp”如何计算

在相同测试样本上，对每张图像计算预测 mask 与 GT mask 的 IoU：

```text
IoU_i = |M_pred ∩ M_gt| / |M_pred ∪ M_gt|
```

然后对测试集求宏平均或样本平均：

```text
mIoU_MedV = (1 / N) × Σ_i IoU_i(MedV-Agent)
mIoU_IBIS = (1 / N) × Σ_i IoU_i(IBISAgent)
ΔIoU = mIoU_MedV - mIoU_IBIS = 0.0058
```

当 IoU 以百分制表示时：

```text
0.0058 × 100 = 0.58 percentage points = 0.58 pp
```

因此，应写：

> 相比 IBISAgent 基线，平均 IoU 提升 `0.58` 个百分点（pp）。

不应写：

> IoU 相对提升 `0.58%`。

后二者语义不同：若基线 IoU 为 `0.70`，绝对提升 `0.0058` 的相对增幅是 `0.0058 / 0.70 = 0.83%`，而不是 `0.58%`。

#### 面试标准回答

> IoU 的 0.58 指绝对百分点差：在完全相同的测试集上，MedV-Agent 的平均 IoU 减去 IBISAgent 的平均 IoU 等于 0.0058，换算为百分制是 0.58 pp。实验对比中保持测试图像、GT、最大交互预算和停止规则一致；我还会报告 Dice、HD95、均值方差与显著性检验，避免仅凭单一均值说明效果。

### 4.3 必须区分的三个效率指标

| 指标 | 统计内容 | 可与 IBISAgent 比较？ | 用途 |
|---|---|---|---|
| 分割交互步数 | `add_bbox + add_point` / 点击数 | 可以，但需统一起始提示与终止规则 | 支撑“降低 26%” |
| 端到端工具调用数 | `classify + detect + add_bbox + add_point + stop` | 通常不宜直接比较 | 衡量系统完整成本 |
| 端到端耗时 | VLM 推理 + API 调用 + 分割推理 | 可以，但需相同硬件/并发/服务配置 | 衡量部署可用性 |

## 5. 可能被问的问题与参考回答

### A. 项目动机与临床逻辑

#### Q1：为什么不直接做分割，非要引入分类和检测？

**回答：** 分割是最终目标，但小病灶、低对比度超声边界和复杂内窥镜背景会导致直接分割初始化不稳定。全图筛查分类提供“是否存在病灶、病灶类型或风险”的语义先验；检测提供候选病灶的空间先验；分割将粗定位转为像素级边界。辅助任务不是并列 KPI，而是降低分割搜索空间、改善初始化并减少无效交互。

#### Q2：临床上一定是“分类→检测→分割”吗？

**回答：** 不存在所有病种通用的唯一固定顺序。我采用的是临床阅片中常见的渐进式抽象：全局异常筛查、候选病灶定位、边界精细量化，再做 ROI 级表征。对于用户已指定靶病灶的任务，Agent 可跳过全图筛查；对于筛查明确正常的样本，可提前停止。

#### Q3：为什么 ROI 分类放在分割之后？

**回答：** 全图分类适合做筛查，但良恶性或病灶表征往往依赖病灶形态、边缘、内部回声/纹理和尺寸。分割后得到 ROI 或其外接框，可减少背景干扰，使病灶表征更贴近临床观察过程。

#### Q4：Kvasir-SEG 只有 polyp 标签，怎么做分类？

**回答：** 在 Kvasir-SEG 中，分类不应包装成良恶性诊断，而是“息肉存在性筛查”。它服务于是否进入定位和分割流程；核心评估仍是息肉检出与分割质量。

#### Q5：这个工作是否只是把几个模型串起来？

**回答：** 模型服务化只是工程基础。算法部分包括：将辅助任务建模为服务分割的语义/空间先验；用 VLM 学习动态工具调度和提前停止；通过 CPR v2 对事件级状态增益、工具间可验证信息流、交互成本和非对称风险进行联合优化。是否有算法价值必须通过固定流水线、终局奖励 RL 和消融实验证明。

### B. 架构与工具调用

#### Q6：Qwen3-VL-8B 在系统里负责什么？它直接输出 mask 吗？

**回答：** 不直接输出 mask。Qwen3-VL 是策略与决策层：理解自然语言任务和工具反馈，选择调用分类、检测、框提示、点提示或停止动作，并生成工具参数。BioMedCLIP、Grounding DINO、MedSAM2/IMISNet 分别执行分类、检测和像素级分割。

#### Q7：完整工具链是什么？

**回答：** 阳性复合病例的主链路是：全图 `classify` 筛查 → `detect` 产生候选框 → `add_bbox` 初始化分割 → 必要时 `add_point` 修正 → 带 `region` 的 `classify` 对 ROI 表征 → `stop_action`。正常筛查且置信度满足阈值时，允许 `classify → stop`。

#### Q8：检测框怎样传到分割模块？

**回答：** 检测输出框被归一到 `[0, 999]` 的 Agent 坐标空间，Agent 以该框或其微调框作为 `add_bbox` 参数。CPR 中计算检测框与 `add_bbox` 框的 IoU，以判断模型是否真正复用了检测结果。

#### Q9：ROI 分类如何真正使用分割结果？

**回答：** Agent 在分割完成后从最终 mask 得到外接区域，调用分类工具时传入 `region`。分类服务会将归一化区域恢复到像素坐标，裁剪原图 ROI 后进行 BioMedCLIP 推理。奖励中用 ROI 区域对最终 mask 的覆盖率衡量“分割→ROI 分类”的对齐程度。

#### Q10：为什么使用可替换后端，而非端到端训练一个大模型？

**回答：** 医学数据规模有限，端到端联合训练分类、检测、分割模型成本高且替换困难。解耦架构使后端模型可独立升级，研究重点放在可迁移的工具调度策略。代价是延迟和误差传播，需要通过异步服务、状态复用、信息流奖励和端到端评估控制。

### C. SFT 数据、自动轨迹与 GRPO

#### Q11：约 60k 条轨迹如何生成？是否人工标注？

**回答：** 基于已有 segmentation mask 自动派生，而不是重新人工标注整条轨迹：mask 外接框用作检测框和分割初始框；预测与 GT 的 FP/FN 区域用于产生正负点；标签用于全图筛查与 ROI 表征；通过规则模板拼接为分类、检测、分割和临床复合链路。面试时应给出各数据集、各任务的实际条数和去重方式。

#### Q12：规则轨迹会不会导致模型只会背模板？

**回答：** 这是风险。SFT 只负责工具格式、坐标表达和临床先验；RL 阶段不提供固定动作轨迹，而是通过多个 rollout 让模型探索。还应构造正常提前停止、已知目标跳过筛查、检测失败后重试和低质量 mask 继续修正等分支，以避免所有样本机械执行同一顺序。

#### Q13：为什么使用 GRPO 而不是 PPO？

**回答：** GRPO 对同一输入采样多条轨迹，根据组内相对奖励构造优势，不需要额外训练 value/critic 网络，适合工具环境中高成本、多轮且奖励可验证的策略优化。PPO 也可用，但 critic 在多工具、长上下文场景会增加训练复杂度和不稳定性。

#### Q14：SFT 和 RL 各解决什么问题？

**回答：** SFT 学基础能力：工具 schema、坐标格式、初始工具顺序和临床先验。GRPO 学策略优化：何时需要筛查、检测框是否复用、是否继续点修正、何时停止，以及如何在质量、成本和安全风险间权衡。

### D. CPR v2：奖励函数与创新点

#### Q15：请写出 CPR v2 的核心公式。

**回答：** 对复合诊断辅助分割任务，当前实现可概括为：

```text
R = 0.60 × Q_terminal
  + 0.20 × Q_process
  + 0.10 × Q_synergy
  + 0.05 × Q_policy
  + 0.05 × Q_format
  - C_action
  - P_safety
```

其中：

```text
Q_terminal = 0.25 × Q_detection
           + 0.45 × Q_segmentation
           + 0.30 × Q_ROI_classification
```

终局质量中分割权重最大，因为它是本项目的主目标；其余项用于让辅助任务真正服务于分割。

#### Q16：事件级过程奖励如何计算？

**回答：** 每次分割动作记录 `mask_before` 与 `mask_after`，用分割质量的变化计算：

```text
gain_t = quality(mask_after_t) - quality(mask_before_t)
```

其中 `quality` 综合 IoU 和 Dice。检测、筛查分类和 ROI 分类按该次事件实际返回结果评分；工具失败直接给负增益。这样能把奖励归因到具体调用，而不是只在最后给一个 mask 分数。

#### Q17：跨工具协同怎么量化？

**回答：** 不是只判断工具是否出现，而是检查上游输出与下游输入是否对齐：

```text
S_triage→det：筛查分类发生在检测前，且病灶存在性/风险判断正确
S_det→seg：IoU(bbox_detect, bbox_add_bbox)
S_seg→ROI：coverage(region_classify, final_mask)
Q_synergy：上述可用项的平均值
```

这说明分类、检测和分割并非独立完成，而是在可验证地传递语义和空间信息。

#### Q18：筛查分类正确并不等于“帮助了检测”，这是不是伪因果？

**回答：** 是的，当前规则奖励证明的是流程一致性和信息传递，而不是严格的因果效应。因果贡献要通过消融验证：去掉筛查分类、替换为随机/错误筛查结果、固定流水线与完整 Agent 对比其分割 IoU、漏诊率、平均交互步数。论文中应明确这是训练期可验证代理信号，而不是直接声称分类结果造成了检测提升。

#### Q19：为什么要加入动作成本？

**回答：** 仅以终局 IoU 作为奖励，会鼓励模型在已足够好的 mask 上继续调用点提示，或尝试无关工具。动作成本区分基础调用、重复参数、任务无关调用、失败调用和高质量后的无效细化；但必须和终局质量、安全惩罚共同使用，防止模型为节省步数过早停止。

#### Q20：漏诊风险怎么编码？

**回答：** 对恶性/病灶样本，判断为 normal、未检测到目标或分割质量很低会产生较高惩罚；将 benign 判成 malignant 的惩罚相对较低。风险项是训练阶段的偏好编码，不替代临床诊断；实验需要同时报告 Sensitivity、Specificity、假阳性率和漏诊率。

#### Q21：正常样本提前停止会不会造成漏诊？

**回答：** 正常提前停止只在筛查判断正常且策略满足条件时被允许；对于 GT 非正常病例，筛查为 normal 会触发较大安全惩罚。实际部署中应使用保守阈值，并把低置信度筛查导向检测而不是直接结束。

### E. 实验、指标与可信度

#### Q22：26% 的步数下降是怎么计算的？

**回答：** 使用阳性测试病例，在相同最大交互预算和停止规则下，统计每例完成分割所需的有效分割交互次数。MedV-Agent 统计 `add_bbox + add_point`，IBISAgent 统计其正/负点击；分别求平均后按 `(S_IBIS - S_MedV) / S_IBIS × 100%` 计算。分类和检测不会混入这个指标，它们另报端到端总调用数。

#### Q23：IoU 提升 0.58% 是什么意思？

**回答：** 准确说法是提升 0.58 个百分点，不是相对提升 0.58%。在同一测试集上，平均 IoU 的绝对差是 `0.0058`，换成百分制就是 `0.58 pp`。比较对象是 IBISAgent 基线，需保持图像、GT、交互预算、终止条件和评估脚本一致。

#### Q24：0.58 pp 会不会太小？

**回答：** 单看均值不能判断价值，需要看置信区间、不同随机种子、病例难度分层，以及是否同时减少交互步数和漏诊风险。对高基线分割任务，小幅 IoU 增益也可能有价值，但必须报告标准差、配对统计检验和困难病例上的结果，不能只报一个均值。

#### Q25：IBISAgent 是什么基线，为什么选它？

**回答：** IBISAgent 是多轮交互式医学分割 Agent，核心是通过正负点击和 mask 反馈迭代改善分割。它与本项目在“多步策略、工具反馈、SFT+GRPO”上最可比。差异是 IBISAgent 聚焦单一分割工具的点击规划；MedV-Agent 重点研究分类语义和检测空间先验如何辅助分割，并优化跨工具协同与临床风险。

#### Q26：怎样保证与 IBISAgent 的对比公平？

**回答：** 保证测试集、数据预处理、GT、图像分辨率、最大交互轮数、终止规则和分割质量评估脚本一致；明确是否共用分割后端。若后端不同，必须同时报告“端到端系统对比”和“固定分割后端下的策略对比”，否则不能把结果完全归因于策略。

#### Q27：最重要的消融实验是什么？

**回答：** 至少包括：

1. 直接交互分割 vs 固定临床流水线 vs 动态 Agent；
2. 去掉全图筛查分类；
3. 去掉检测→分割框复用；
4. 去掉 ROI 分类；
5. Outcome-only reward vs CPR v2；
6. 去掉事件级过程奖励、协同奖励、动作成本、安全惩罚；
7. 将正确筛查结果替换为随机或错误结果，验证筛查先验的真实贡献。

#### Q28：应该报告哪些指标？

**回答：** 分割主指标为 Dice、IoU、HD95；筛查指标为 Sensitivity、Specificity、F1；检测指标为 Recall、mAP、bbox IoU；Agent 行为指标为分割交互步数、端到端调用数、提前停止正确率、失败调用率和检测框复用率；安全指标为病灶漏诊率和正常样本假阳性率。

### F. 相关工作与创新边界

#### Q29：和 IBISAgent 的核心区别是什么？

**回答：** IBISAgent 重点是单一交互分割工具中的点击策略：如何通过正负点和 mask 反馈逐步改进分割。MedV-Agent 将研究问题扩展为诊断辅助分割：全图分类做语义筛查、检测做空间定位、分割做边界精描、ROI 分类做病灶表征，并通过 CPR v2 优化跨工具信息流、成本和漏诊风险。

#### Q30：和 MedVL-SAM2 的区别是什么？

**回答：** MedVL-SAM2 是端到端的统一 3D 医学 VLM，重点在 3D 表征、语言—像素对齐和 `[SEG]` token 驱动的分割。MedV-Agent 是解耦的多工具决策框架，重点在如何调度可替换的分类、检测和分割后端，并学习临床过程中的信息复用和停止策略。

#### Q31：你的创新点是什么？

**回答：** 三点：

1. 将分类和检测从并列任务重构为服务于高精度病灶分割的语义/空间先验，形成筛查—定位—精细分割—ROI 表征的临床闭环；
2. 显式量化筛查→检测、检测→分割、分割→ROI 分类的可验证信息流，而不是简单拼接工具输出；
3. CPR v2 将终局质量、事件级增益、协同、无效交互成本和非对称漏诊风险联合纳入 GRPO 优化。

#### Q32：哪些部分是工程，哪些部分是算法？

**回答：** API 服务、后端模型部署、数据格式转换和会话资源管理属于工程基础；层级式任务建模、动态工具策略、事件级过程奖励、可测量信息流协同和安全约束属于算法设计。论文必须用严格基线和消融证明后者带来的增益。

## 8. 最终答辩式总结

> MedV-Agent 的核心不是把多个视觉模型简单拼接，而是把分类和检测重新定义为分割的辅助先验：全图分类负责异常筛查，检测负责候选定位，交互式分割负责边界精描，ROI 分类负责病灶表征。为优化这条临床渐进式链路，我使用 Qwen3-VL 进行动态工具调度，并设计 CPR v2 奖励同时约束最终质量、每步增益、跨工具信息复用、无效交互和漏诊风险。实验上，我以 IBISAgent 作为多轮交互分割基线，在 BUSI、Kvasir-SEG、TN3K 上获得 26% 的分割交互步数下降和 0.58 pp 的 IoU 绝对提升；后续重点是补齐完整 GRPO 消融、统计显著性和跨数据集泛化验证。
