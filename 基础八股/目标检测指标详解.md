# 目标检测指标详解与代码实现

配套代码：[detection_metrics_demo.py](../面试手撕/detection_metrics_demo.py)。运行：`python detection_metrics_demo.py`。代码使用普通 `xyxy` 框、同类同图的一对一匹配和 101 点插值 AP，便于理解核心算法。输入的预测框应已完成模型解码及该检测器需要的 NMS 等后处理。

## 1. 先判断 TP、FP、FN

预测框要同时满足**类别正确**、与同图同类真实框的 IoU 达到指定阈值、且该真实框尚未被更高分预测匹配，才算 TP。其他保留下来的预测框算 FP；没有被匹配的真实框算 FN。重复检测同一个目标时，通常仅最高分的一个框为 TP，其余为 FP。

`IoU = 预测框与真实框的交集面积 / 并集面积`。例如预测框与真实框的 IoU 为 0.68，它在 AP50 的匹配标准下可算 TP，在 AP75 下则算 FP。IoU 阈值用于判断框是否匹配，置信度阈值用于决定是否保留预测框；二者不是同一个阈值。

## 2. 固定置信度阈值下的 P、R、F1

- `Precision = TP / (TP + FP)`：已预测出的目标有多少正确；FP 越多通常越低。
- `Recall = TP / (TP + FN)`：真实目标有多少被找到；FN 越多通常越低。
- `F1 = 2PR / (P + R)`：P 与 R 的调和平均。

例如 `TP=3, FP=2, FN=1`，则 `Precision=0.6`、`Recall=0.75`、`F1≈0.667`。这些值取决于置信度阈值和 IoU 匹配阈值。调高置信度阈值，预测框减少，P 往往提高、R 往往下降，但不是数学上的绝对保证。

## 3. AP 与 mAP

AP 不只取某一个置信度阈值。对**一个类别**的所有预测框按置信度从高到低排序，逐个纳入预测，得到一系列累计 Precision、Recall；由 P-R 曲线求面积或按评测协议插值，得到该类别的 AP。

- `AP@0.50`：对单个类别可这样注明其在 IoU=0.50 下的 AP；COCO 汇总表的 `AP50` 已跨类别平均。
- `mAP50`：各类别 AP50 的平均。常被口语称为 mAP@0.5；`mP50` 不是标准写法。
- `AP@0.75`：对单个类别可这样注明其在 IoU=0.75 下的 AP；COCO 汇总表的 `AP75` 已跨类别平均，更看重定位精度。
- `mAP50-95`：在 IoU 0.50、0.55、…、0.95 共 10 个阈值分别计算每个类别 AP，再跨阈值和类别平均。COCO 通常把这一口径称为 AP，常作为主指标。

不同评测工具的 AP 插值、忽略区域、crowd 标注、最大检测数等细节不同。配套代码刻意只实现核心逻辑，结果不应直接当作 COCO 官方评测结果。

## 4. 尺度、速度和业务指标

COCO 还会报告 `AP_S`、`AP_M`、`AP_L`，分别观察小、中、大目标表现；尺度由标注的 `area` 字段按该协议划分，**不一定等于真实框面积**，也不是按预测框尺寸分类。实际项目还应看各类别 AP、固定阈值下的 P/R、误检/漏检案例和端到端延迟。FPS 与延迟受硬件、batch、输入尺寸、预热、数据传输和后处理影响，应统一环境比较。

## 5. 配套代码的匹配流程

```text
对每个类别、每个 IoU 阈值：
    取该类别所有预测框，按 score 降序排序
    对每个预测框：
        只寻找同一张图、同一类别、尚未匹配的真实框
        选 IoU 最大者；达到阈值则 TP，否则 FP
    逐项累积 TP/FP，计算 P-R 曲线和 101 点插值 AP
跨类别平均得到 mAP50；跨类别和 10 个 IoU 阈值平均得到 mAP50-95
```

配套示例有 3 个真实框、5 个预测框。其中类别 0 的预测排序为 TP、FP、TP、重复框 FP；类别 1 的预测框 IoU 约为 0.68。因此在固定 `score≥0.5`、`IoU≥0.5` 时，`TP=3, FP=2, FN=0`，`Precision=0.6`、`Recall=1.0`、`F1=0.75`；`mAP50≈0.9175`、`mAP50-95≈0.6175`。后两个值由代码中的 101 点插值口径得到。
