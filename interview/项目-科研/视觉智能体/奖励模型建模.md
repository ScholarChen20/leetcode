## CPR 奖励函数设计思路

### 核心一句话

> 传统奖励问"结果有多接近 GT？"，CPR 改问"**Agent 的推理过程有多像专家医生？**"

### 根本问题

现有方法（IoU/Dice/Acc）都是**结果导向的标量奖励**，有三个致命缺陷：

1. **信用分配难** — 多轮交互不知道哪一步贡献大
2. **过程无语义** — 只看像素匹配，不看临床合理性（可能学出"IoU 高但临床不合理"）
3. **任务间无迁移** — 分类/检测/分割各自独立，复合任务协同性无法体现

### 三个创新模块

**模块 A：步骤级临床推理分（Step-Level Clinical Reasoning）**
把 Agent 每一轮 `(观察, 动作)` 拆成四维打分：

| 维度 | 问什么 |
|------|--------|
| 定位准确性 | 这一步准确指向目标区域了吗？ |
| 信息增益 | 这一步提供了新诊断信息吗？（无增益=浪费步骤） |
| 临床一致性 | 操作顺序符合临床逻辑吗？（先定位→再细化→后判断） |
| 决策置信度 | 决策有没有依据（推理文本/logit entropy）？ |

**模块 B：跨任务协同分（Cross-Task Synergy）**
评估工具间**信息流**：detect 的框被 add_bbox 复用 → +bonus；被忽略 → -penalty；跳过关键步骤 → -penalty。让 Agent 学会"前一步结果为后一步服务"。

**模块 C：对抗性临床一致性（Adversarial Clinical Consistency）**
引入一个"临床判官"（Clinical Judge），评估决策是否医学合理、有无危险操作、漏诊/误诊风险。

### 完整公式

```
CPR = λ₁·Σγᵗ·step_score    # 步骤级（定位/信息增益/一致性/置信度）
    + λ₂·synergy_score       # 跨任务协同
    + λ₃·judge_score         # 临床判官
    + λ₄·final_result        # 传统几何指标（保底）
    - λ₅·safety_penalty      # 漏诊/误诊不对称惩罚
```

### 四个核心卖点（相对现有方法的范式转变）

| 维度 | 传统 | CPR |
|------|------|-----|
| 粒度 | 轨迹级标量 | **步骤级** |
| 语义 | 几何指标 | **临床语义** |
| 任务关系 | 各自独立 | **跨任务协同** |
| 安全 | 无 | **漏诊/误诊不对称惩罚** |

### 关键工程判断

文档特别强调了**渐进式实现**（Phase 1 规则版 CPR 零额外模型 → Phase 2 加临床判官 → Phase 3 安全约束），并且计算开销可控（规则版仅 +7%）。这是把数学推理领域的 PRM 思想**首次迁移到医学视觉 Agent** 的卖点。

---

一句话总结：**它不是"更好的 IoU"，而是改变奖励范式——从"结果对错"到"过程像不像专家"。**
